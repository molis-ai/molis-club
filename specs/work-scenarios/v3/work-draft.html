    和你现在的用法比

    不用把工作搬进 AI，AI 来你手边。

    每天用 AI 干活，多半是下面几种做法的组合。

    现在的做法你要做的做完的东西在哪下次接着做
    问 AI对话助手打开对话框，交代背景，贴报错和代码。在对话里，要自己搬回仓库和文档。新开对话，再讲一遍。
    在 GitHub 上把 issue 指派给 Agent编码 Agent 的云端任务先把 issue 写清楚；目标和设计约束，得自己写进 issue 或仓库。在一个 PR 里。换个 Agent，从 issue 和 PR 重新读起；你没写进去的，它不知道。
    自己拼一套CLAUDE.md、进度文件、脚本、自己写 MCP每个 Agent 各写一份规矩，收工写进度，脚本和 MCP 自己维护。散在仓库、文档和各个对话里。看进度文件写得好不好；你写的工具，往往只有一个 Agent 会用。
    在 Molis Work 里选中，点一下；目标、约束和上次进展跟着走。回到同一页，记着出处和依据。谁来做都读同一组目标；你做的工具，每个 Agent 都能调用。
    现在的做法你要做的做完的东西在哪下次接着做
    问 AI对话助手和它的项目功能把资料传进去，开口交代要什么。在对话里，要自己复制回文档。资料留在那个对话或项目里；换个 AI，再传一遍。
    文档工具里的 AI笔记、文档软件自带的在文档里叫它，问一句改一段。在那份文档里。只认得这个工具里的东西；视频、邮件、笔记库得先搬进来。
    自动化工具连应用、画流程先画好流程、连好账号，规则写死。按流程送到各个应用。流程不看你在写什么；要改，得回去改规则。
    一句话做应用说一句，生成一个小应用说一句，得到一个独立的小应用。在那个应用里。它不认识你的文档，不会在你写的时候递到手边，别的 AI 也用不上。
    在 Molis Work 里接着写你的，下一步递到手边。落进该在的地方，记着出处。换个 AI，读的是同一页；你做的选题库，在哪都能一点放进去。

    目前还不如它们的地方：写代码本身，编码 Agent 更强，我们接住它们、不和它们比；要装应用、跑一个常驻在本机的服务；团队、多设备、手机都还没有；目前只有 macOS。

    目前还不如它们的地方：今天能下载的开源版要从源码安装，更适合写代码的人；和别人一起编辑、多设备、手机都还没有；目前只有 macOS。

    三分钟接上

    1. 装上（macOS、Node.js 24+、pnpm）
      git clone --branch v0.2.0 https://github.com/molis-ai/molis-work.git cd molis-work pnpm install --frozen-lockfile && pnpm install:local ~/.goalboard/bin/goalboard service install --home ~/.goalboard --confirm ~/.goalboard/bin/goalboard demo create --confirm
    2. 接上 Agent：打开 127.0.0.1:4173，进入示例项目，在「设置 → Runtime」预览并确认接入 Claude Code 或 Codex。
    3. 新开一个会话，说一句
      使用 GoalBoard 连接示例项目，打开一条 Goal，告诉我当前判断、已经做成了什么、下一步和完成要求。

    去够更难的问题

    执行越来越便宜，难的是知道该解决什么。把时间花在一个人想不清、机器也给不了答案的问题上。

    比如：啃下那个一直不敢动的架构问题。

    比如：想透用户为什么第二个月就走了。

    去创造

    决定什么值得做、做给谁、做到什么程度。机器给方案，判断留在你手里。

    比如：做一个只有你想得到的小工具。

    比如：决定下一个系列写什么、写给谁。

    留给生活

    早点合上电脑。工作接得上，就不用把它带回家。

    比如：周五不用加班写发布说明，准点走。

    比如：写那篇一直想写、不为交差的长文。
