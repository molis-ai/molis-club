## 一、功能清单

### A. 平台（每个 Home 一份，所有插件共用）

**1. 打开与开始**
- 每天打开先停在项目选择页，上次的项目已预选，回车进入；每个项目一行写着当前目标、几件等你确认、完成数。【main】
- 项目首页「今天的工作」：日期条、正在推进的 Goal、当天事件、随手记、手边的内容。【main】
- 新建项目：勾选来源（文件夹、上传文件、粘贴网页、Gmail 最近 7/30 天），读完正文（长了分批，原文存进 Cognia），生成带来源的工作总结、项目建议和待办草稿，采用后项目里就有摘要文档、全部来源和待办；没配模型也能先把资料带进来。真实 Gmail 20 封已走通。【main】

**2. 底栏助理**
- 任何页面从底栏叫出，知道你在看哪一页、选中了哪段；@ 引用内容，/ 选能力，读 PDF 和图片。【main】
- 建议是操作卡：带好完整参数，点一下执行；能撤销的改动做完给你撤销。【main】
- 需要你选时出问题卡（单选、多选、带推荐理由），答完原任务接着做；Coding 等你回答的问题也用同一张卡。【main，10/13–14】
- 子任务并行、任务板上看进度；写代码的部分交给 Coding。【main】
- 到期跟进、失败提醒，守勿扰、暂停、稍后。【main】
- 助理工作可以展开成主区的一个标签。【main，#489】
- 推荐动作、操作卡、问卷卡与对话合成一条动线；「下一步」按钮挪到输入框同一行。【分支：情境线、交互线】
- 你在 Agent 干活时补一句，看得到它读到没有、还没读、已撤回。【分支：回执线】

**3. 情境动作（「手上有一样东西时，能对它做什么」）**
- 选区浮条：在文档里选中一段，旁边出现两类按钮，左边是这个插件的工具（加粗、标题、评论……），右边是按情境排序的动作（最多 3 个）。取代了原来底部的动作条，Pages 已迁到浮条。【main】
- 现在可用的选区动作：
  - Pages：解释、提出反例、读者视角、写作教练、展开论述、接着写、拆成行动项、提炼要点、总结、列出大纲、比较异同、翻译、合成新文档等；
  - Goals：拆成目标步骤（提交为提案）、记录进展（记到所属 Goal）；
  - 待办：记成待办；灵光：记下灵光（这几个对任何内容都可用）；
  - 搜索：在项目里查找。【main】
- 对象动作：Feed 消息可以加入 Inbox、保存为资料、升格为 Goal、忽略；Inbox 事项可以做完、忽略、整理成文稿。【main】
- 一句话新建：每个插件新建按钮旁一个「✦」，写一句话由助理按该插件的格式建好一条。【分支：情境线，部分在 main】
- 选中零输入创建：选中内容后，浮条推荐最合适的去处（记成待办、记成炼金术士想法……），点一下就建好，不用再输入。【分支：情境线】

**4. 右栏**
- 讨论（项目群与公开 Thread，需自部署本地 Server）、浏览器、文件三格；灵光也在右栏。【main】
- Shelf 移进右栏成为一格；右栏里的东西可以拖到或发到左边的当前位置，同一个动作池。【分支：情境线】
- 侧栏浏览器：助理在里面操作网页，点击、输入逐步确认，随时接手，停下或关总开关立即交还。【main】
- 「电脑」格：助理操作 Mac 上的其他应用（已在真机走通 TextEdit、计算器），实时画面、确认卡、「本轮内允许在这个应用里操作」、操作记录存进文件；终端、系统设置、密码框是禁区。【分支：Computer Use，进行中】

**5. 找东西与记住东西**
- ⌘K 搜索全部插件的内容（包括没打开过的），两个字的中文、Q4 这种短词也能搜，点开由原插件核对并定位。【main】
- 记忆：个人与项目分开记；自动记下的先成候选，你采纳才算；看得见、改得了、撤得回、删得掉，可导出导入。【main】

**6. 放置**
- 把一样东西移动或复制到别的插件、建链接、绑到 Goal、找相关的东西。【main】

**7. 能力目录与授权**
- 每个插件把能力登记一次，页面、助理、工作流、外部 Agent 从同一个目录调用；按调用方逐项授权，外部 Agent 只看得到授权给它的能力。【main】
- 写文件、跑命令、推送先进审查队列；能撤销的直接做；被取消或撤权的调用不再写入。【main】
- 每次调用留记录，带诊断编号；设置里按编号查。【main】

**8. 角色与提示词**
- 系统、插件和你自己的角色、提示词都在设置里可见可改，可以恢复默认。【main】
- 从 Codex、Claude Code、Cursor、OpenCode、Grok Build 的本机配置导入规则和 Skills 成为角色，用内置 Prologue 或原生 Agent 运行。【main】

**9. 外部 Agent 接入**
- Codex、Claude Code、OpenCode、Pi Agent、Grok Build 内置接入（先预览再写入，失败回滚）；其他 Agent 经 MCP 和统一 Skill。【已发】

**10. AI 运行时与连接**
- 模型、密钥、预算配一次，兼容 OpenAI 与 Anthropic 接口，密钥加密存本机。【main】
- 约 45 个服务的连接方式；从 Notion、飞书、Google Docs 导入文档。【main】
- 判断规则：自己定义判断（「这条要不要进 Inbox」「下一步做什么」），用在 Feed 捕捉、Inbox 下一步和首页推荐上。【main】

**11. 桌面**
- macOS App；菜单栏胶囊，点开看当前项目、聚焦的 Goal、状态和下一步；Goal 绑定的终端面板；截图和文件直接拖进窗口。【已发 / main】
- Shelf 全局热键与拖放轮盘。【main，随 Shelf 移右栏改道中】

**12. Issue（团队内部开发用，不上官网）**
- 任何地方按 ⌘⇧I，写一句话、粘贴截图，回车就走；助理在后台起标题、判类型并保存，可撤销；信息不够时留在列表顶部等你补。【main，10/10–11 合入，未验收】
- 用户 10/16：Issue 是团队自己内部开发用的。官网任何地方都不展示它，包括产品全景屏里窗口右上角的 Issue 按钮、插件墙和插件列表。

### B. 项目插件（项目里按需添加；Goals 每个项目都带）

**Goals**（69 项动作）
- 一句话意图就能存成 Goal，不用先选规划。【已发】
- 约定与要求：要达成什么、做到什么算完成；要求可以设成「必须由人验收」。【已发】
- 记一笔：随手备注、同步进展、问题与风险。【已发 / main】
- Agent 报告工作事实、记录进展；报告不能代替你的决定或收尾。【已发】
- 请求决定：AI 提出问题、至少两个选项和各自影响，进决定中心等你拍板。【已发】
- 结构提案：Agent 提新 Goal 或新依赖，你逐项或整组确认才生效。【已发】
- 依赖画布、关系图检查（循环、缺失）、变更影响分析（哪些上下游受影响、哪些工作还能复用）。【已发 / main】
- 规划方法：项目 > 个人 > 内置，按工作类型、领域、行业叠加。【已发】
- 项目长期说明：经你同意才保存，所有 Runtime 读到同一份。【已发】
- 收尾：显式提交，核对当前要求、真实依据和阻塞；不满足就「收尾未生效」并写明原因，Goal 仍在进行中。完成后可以说明原因继续。【已发】
- 输入：把文档、问卷、演示稿、表格、Shelf 材料、Feed 消息、成果版本记为 Goal 的输入；助理和 Agent 提的只算「待确认」。【main】
- 交付物：收尾时选成果库里的一版，或把文档当场「固定并交付」；助理和 Coding 只能提议。【main】
- 归档、回收站；Goal 绑定的终端（不自动改绑、不自动发送）。【已发】

**Sessions**（18 项）
- 会话目录：各 Runtime 的会话关联到项目和 Goal，恢复原生会话接着做。【已发】
- 交接包：按当前 Goal 生成交接草稿，改好后在目标 Runtime 新开会话送出。【已发 / main】
- 给某个会话发消息，带送达回执（已接收 / 未确认 / 被拒可重试）。【main】

**Inbox**（15 项）
- 只放需要你介入的事，每条写明为什么进来、下一步是什么。【main】
- 绑一个判断规则，自动给出下一步建议；建议不会自动处理事项。【main】
- 勾选几条事项「整理成文稿」，生成 Pages 文稿（材料快照随文稿保存，失败可恢复，不会自动完成事项）。【main】
- 转为待办。【main】

**Feed**（35 项）
- 来源：研究库、RSS/Atom、网页查询、YouTube、GitHub、Gmail；手动或按间隔自动拉取，可暂停。【已发】
- 捕捉规则：关键词或判断能力，命中的进 Inbox；可以先拿最近五条预览。【main】
- 消息可以保存为资料、忽略、恢复、升格为 Goal（成为 Goal 的输入）。【已发 / main】
- 外部内容一律当资料，不会变成给 AI 的指令。【已发】

**Schedule**（12 项）
- 每天定时运行的对话任务，到点由项目 Agent 按说明执行（只读）。【main】
- 替其他插件准时提醒，提醒进 Inbox；本地服务没开时不响。【main】

**成果**（17 项）
- 项目里人要留存、引用的固定版本；各版本可回看、可比较。【已发（基础）/ main】
- 导入任何本地文件，或用已连接的账号导入 Notion、飞书、Google Docs 文档。【main】
- 这一版被谁引用；交给某个插件的输入、交给助理、交给 Coding、作为工作流的起点；文本可以「从这一版继续」。【main】

**Coding 一族**（Coding 19 项、Files 6、Git 10、Diff 2）
- 编码会话：每一轮选方式（讨论、规划、修改、执行、评审、并行写入）；运行中回答提问、补充要求、暂停、继续、停止，或换模型。【main】
- 计划：规划轮次形成计划，你确认后固定，再按计划执行。【main】
- 执行报告、变更固定成版本；Files 浏览与固定快照；Git 提交、分支、推送、开 PR 都先生成审阅，你批准才执行；Diff 比较固定版本。【main】
- 同一项目的多个 Coding 会话共用项目工作板，各占一块，互相交接和提问。【分支：采用线】

### C. 个人插件（每个项目里都在，项目可以隐藏）

**待办**（25 项）
- 视图：今天、在等谁、未安排、即将到期；截止、计划处理、提醒三种日期；重要只能本人标。【main】
- 每件待办记着来源和形成原因（手动、材料、助理、Inbox、灵光、开始使用时）；可以关联 Goal、材料、其他待办（要等它、拆分、合并）。【main】
- 批量处理；每次修改都可撤销。【main】
- **从材料整理待办**：给它邮件、会议记录这类材料，找出要你处理的事、你做过的承诺、在等别人的事和建议，和已有待办比对后列成候选，你逐条采用、合并或忽略。【main】

**Jelly**（53 项）
- 日历：一次性和重复事项、分类、按天排列；笔记：置顶、归档、导出 Markdown/HTML。【main】
- 事项与笔记互相关联；笔记里的任务排进日历。【main】
- 按原文逐行或用模型把一段计划拆成待采纳的任务，采纳后才写入。【main】
- 撤销、重做；日历进展汇总（完成、延期）。【main】

**灵光**（19 项）
- 先记下还没想清楚的想法；读取文件（图片识别、音视频转写）和链接（网页、视频字幕、播客音频）。【main】
- 和选中的灵光对话，头脑风暴。【main】
- 转为待办、转成 Jelly 笔记〔按钮〕；任何地方选中内容「记下灵光」〔选区〕。【main】

**Pages**（40 项）
- 文档、文件夹、模板；导入 Notion、飞书导出的 DOCX、Markdown、HTML。【main】
- 选区浮条上的写作动作（见平台第 3 项）；写作助手出候选正文，你确认才写入；助理改过的可以撤回。【main】
- 评论里 @助理，答复回到原评论，不改正文。【main】
- 按材料生成文稿（来自 Inbox）；从文档提取任务卡和知识页；存为成果、导出 Markdown/PDF。【main】

**Forms**（27 项）
- 建问卷，AI 拟题；在本机填写，或导出一个独立 HTML 填写页发给别人，收回答卷文件后导入；逐题汇总，导出 CSV；没有外网链接。【main】
- AI 拟题前先在问题卡里问清楚。【分支：交互线】

**Dataset**（27 项）
- 表格，导入导出 CSV，AI 拟列名，快照与回滚，存为成果。【main】

**PPT**（24 项）
- 写大纲；把一段文字或一篇 Pages 文档由 AI 整理成幻灯片；放映，导出 PPTX（标题、要点、讲者备注、配色，不含图）。【main】

**图片**（13 项）
- 连接 OpenAI、Gemini 或兼容接口生图，历史保存在本机。【main】

**Cognia**（25 项）
- 导入 Obsidian、Markdown 文件夹或上传文件，保留原文和每个版本；全文检索。【main】
- 选 1–5 份资料整理成带引用的草稿；在一个领域里提问，按资料回答，没有依据就不调模型；草稿采纳后成为资料。【main】

**Shelf**
- 把文件放上来处理副本（原件不动）：提取文字、OCR、剪贴板；保存成项目材料；接收 Coding 的报告。【main】

**炼金术士**（56 项）
- 写下一个方向，炼成一组可比较的候选卡，保留或丢弃。【main】
- 对保留的想法做市场空间和实现成本两类研究，证据带真实网址，有调用上限；研究齐了才能记 Build、Hold 或 Drop。【main】
- 在报告上划线批注，据此校准研究方法；Taste 记你的长期偏好（不算市场证据）。【main】
- 市场脉搏：从 Toolify、Watcha、GitHub 抓信号成报告，机会可以转成方向。【main】

**工作流程**（16 项）
- 把插件排成一条线，每两站之间选衔接方式：模板转换、AI 整理、人工交接、判断规则；也可以把任意登记的动作当一步。每次运行留下交接记录。【main】
- 能当站的插件：Forms、灵光、Inbox、Dataset、Jelly、Feed、PPT、Pages；成果库可以当起点。【main】

**插件创作台**
- 描述需求，Agent 先给方案，再在沙箱里写代码和测试，过检查与浏览器验收后装进项目；做出的插件和内置插件一样被助理、工作流、外部 Agent 调用。12 个真实需求里 4 个第一次就做成。【main，预览】

**角色**（在「设置 › 角色」）：见平台第 8 项。

## 四、推断的场景

每个场景先写由什么触发，再列功能链。每一步都标明它靠哪条接线成立；〔助理〕表示能接上，但要靠助理来串。

### S1　开完会、看完邮件，承诺不再丢（每个人）
- 触发：一场会、一串邮件、一份会议录音。
- 链：
  1. 录音进灵光，转成文字【main】；邮件已在 Feed【已发】。
  2. 「整理材料里的待办」：找出要你做的事、你答应别人的事、在等别人的事，和已有待办比对〔助理〕【main】。
  3. 你逐条采用、合并或忽略，每件待办记着出自哪份材料、哪句话【main】。
  4. 有日期的排进 Jelly；在等别人的到期提醒【main】。
- 最后留下：一张来源清楚的待办清单，「在等谁」单独一栏。
- 体现：AI 判断、人采用；每件事有来源；改动可撤销。

### S2　信息很多，只处理该处理的，写的时候有出处（研究、分析、产品）
- 触发：订了十几个来源，月底要交一份行业观察或周报。
- 链：
  1. Feed 定时拉 RSS、GitHub、YouTube、Gmail【已发】。
  2. 捕捉规则把需要你看的送进 Inbox，每条写明原因〔规则〕【main】。
  3. 勾 6 条「整理成文稿」，得到一篇 Pages 文稿，材料快照跟着文稿【main】。
  4. 在文稿里选中一段「提出反例」「读者视角」，选中「下周」那段「记成待办」〔选区〕【main】。
  5. AI 整理成 PPT 大纲，导出 PPTX；文稿存为成果的一版【main】。
- 最后留下：一份能回到原始材料的文稿、一份 PPT、几条有来源的待办。
- 体现：「到处有 AI，但不是到处是对话」；每样东西各有主人，AI 用原处的内容。

### S3　新项目第一天：给一堆材料，还一个能开工的项目（接手新项目、新客户、新岗位）
- 链：
  1. 新建项目，勾选文件夹、Gmail、网页【main】。
  2. 读完全部正文，原文进 Cognia，生成带来源的总结、项目建议和待办草稿【main】。
  3. 采用后项目有摘要文档、全部来源和待办【main】。
  4. ⌘K 搜「报价」，定位到那封邮件【main】；在 Cognia 里提问，按资料回答【main】。
- 最后留下：第一天就有内容的项目。
- 体现：没有空白的第一天；每一句都有出处。

### S4　一个念头，到决定做不做（创业者、产品经理）
- 链：
  1. 一个链接或一段播客进灵光，读出文字，和它头脑风暴【main】。
  2. 写成炼金术士的方向（复制过去〔按钮〕，或选中零输入创建【分支】）。
  3. 炼成候选卡、保留两张，跑市场与成本研究，证据带网址【main】。
  4. 在报告上批注，记下 Build 及理由【main】。
  5. 在报告里选中下一步「拆成目标步骤」，提案等你确认〔选区〕【main】。
- 最后留下：一条有依据的决定，和一棵等你确认的 Goal。
- 体现：从想到做是一条线，判断有证据。

### S5　换了 Agent，工作不用从头讲（开发者）
- 链：
  1. Claude Code 做完的事以进展记在 Goal 上【已发】。
  2. 换 Codex 时用交接包，或新会话自己读同一个 Goal【已发】。
  3. Codex 提的新需求作为提案等你确认【已发】。
  4. 它说做完了，收尾被拒并写明还差什么【已发】。
  5. 推送先进审查【main】；交付物记成成果的一版【main】。
- 体现：完成要核对；Agent 不能自己改题。

### S6　和 Agent 一起写代码，每一轮都留得住（开发者）
- 链：
  1. Coding 会话先做一轮「规划」，你确认计划后固定【main】。
  2. 按计划执行，中途它用问题卡问你，你补一句（读没读到看得见【分支】）【main】。
  3. 提交、推送、开 PR 先出审阅，你批准【main】。
  4. 执行报告固定，交付到 Goal【main】。
  5. 两个会话共用项目工作板，一个做前端一个做后端，互相交接【分支】。

### S7　交给助理一件跑腿的事，每一步都看得见（每个人）
- 链：
  1. 对助理说一句「把这三家的定价整理成表」，它先出问题卡问按月还是按年【main】。
  2. 在侧栏浏览器里打开网页，点击和输入逐步确认【main】。
  3. 需要操作 Mac 上的应用时，在「电脑」格看实时画面，可以「本轮内允许」【分支】。
  4. 结果写进 Dataset 和 Pages〔助理〕；每处改动可撤销，调用留记录【main】。
- 体现：放心让 AI 动手。

### S8　写一篇内容，发到几个平台（内容创作者）
- 链：
  1. 带着想法和材料进 CGS，先讨论、不急着生成【分支】。
  2. 生成几版候选，比较后采用，确认主稿【分支】。

  4. 材料可以来自 Feed、灵光、Pages〔助理〕【main】。
- 最后留下：每个平台一份批准过的稿子和配图，由人去发。
- 体现：AI 出稿，人定稿；全部本机。

### S9　一件每周都做的事，排成流程（团队里牵头的人、重复工作）
- 链：
  1. 工作流程：Feed → Inbox（判断规则）→ Pages（AI 整理）→ PPT【main】。
  2. 每周从 Feed 的新消息开始一次运行，人工交接处停下等你看【main】。
  3. 每段交接留记录【main】。

### S10　缺个顺手的工具，自己做一个（想自己做工具的人）
- 链：
  1. 插件创作台描述需求，Agent 出方案、在沙箱写代码、通过检查后装进项目【main，预览】。
  2. 助理和工作流马上能调用它【main】。

### S11　每天早上第一眼（每个人，日常那一屏）

### S12　用着用着发现问题，随手记下（内部用，不上官网）

  1. ⌘⇧I 写一句话、粘贴截图，回车【main】。
  2. 助理起标题、判类型，保存，可撤销【main】。

## 六、定位：再抽象一层（10/15 对齐）

用户确认的说法：

> **你和 AI 用的是同一个工作台，而且这个工作台会照着你的用法长。**

它和现在两类常见工具不一样：
- 带 AI 的工具：工具是定死的，AI 只是里面的一个功能，人得迁就工具。
- 连了工具的 AI：干完的活留在对话里，人成了 AI 和工具之间的搬运工；开新对话，它又不记得了。

Work 的工作台在中间，人和 AI 都是它的用户。具体是三条：

1. **同一双手（AI 不止在对话框）。** 插件能力登记在同一个目录，人点的按钮和助理、工作流、外部 Agent 调的是同一个动作，所以 AI 做的事直接落进真实的待办、文档和 Goal。
2. **同一份记录。** 活留在工作台里，不留在某个对话里；换 Agent、隔几天回来，读的都是同一份 Goal。
3. **工作台会长（王炸，高级用法）。** 缺的插件让 AI 做，重复的事串成跨插件的工作流，判断写成规则，纠正沉淀成方法；人加的任何东西，马上也是 AI 的新能力，所以越用越好用、越用越像你。

用户的决定：
- 特点「AI 在工作里，不在对话框里」改成「AI 不止在对话框」。
- 「AI 动手，人拍板」很基础，不当特点讲。
- S1 周报、S5 换 Agent 都保留，用作中段的两个 case。
- 灵活性（插件创作台 + 跨插件工作流 + 越用越好用）作为介绍的王炸。

讲「会长」时按实际说：插件创作台是预览，12 个真实需求里第一次做成的只有 4 个；工作流程和判断规则已合入 main、未发版；沉淀分散在各插件里，没有一个统一的地方让用户看到自己攒下了什么。

## 八、页面结构（10/15 对齐，取代第七节的拆拍）

在现有 Folio Work 页的基础上调整，先定内容，再做动画。

**用户的决定**
- 首屏保留「让工作，在人、工具与 Agent 之间继续。」，它讲的是 Work 里流畅丝滑、AI-native 的工作台体验。
- 所有王炸都放在最上面。
- 只讲用户感知得到的能力，不讲原理和实现。
- 结构按「递、接、长」三幕试，后面加「各种干法」和「团队协作」两幕。
- 「里面有什么」不列插件名，按「收、想、写、排、推进」做成图标动画。

**首屏下面的三张王炸（草稿）**
1. 不用开口，下一步就在手边。你在做什么，合适的能力就出现在旁边；需要你选的时候，它问一句，你点一下它接着做。
2. 换了 Agent，接着同一页做。Claude Code、Codex、助理和你，读写的是同一份记录。
3. 怎么干，你说了算。同一套工作台，拼出自媒体运营、创业分析、写研究、带项目的不同干法；缺的工具让 AI 做，长出来的也会递到手边。

**各幕**

| 幕 | 讲什么 | case | 状态要点 |
| --- | --- | --- | --- |
| 递 | 不用开口，合适的能力自己到手边 | 周五写周报，全程不离开这篇周报：Inbox 整理成文稿、右栏 PDF 选一句放进来、选中一句记成待办、做成 PPT 前问一句 | 选区动作在 main；右栏放进左边、做成 PPT 的推荐在情境线分支 |
| 接 | 换谁来做，都接着同一页 | 周一 Claude Code、周三 Codex「接着做」、菜单栏看进度、说做完了但还差一条 | 已发版 |
| 长 | 越用越顺手，长出来的也递到手边 | 周报存成每周的流程，下周选中就递来「运行：周报」；创作台做一个客户反馈看板 | 工作流程在 main；选中运行流程在分支；创作台为预览 |
| 各种干法 | 同一套工作台，拼出不同干法 | 以图标归位开场，再拼成自媒体运营、创业项目分析、做研究、独立开发、你自己的干法 | CGS 在分支；动画小样见 `work-recipes.html` |
| 团队协作 | 分析、讨论、待办、执行在一处接上 | Dataset 做经营分析 → 结论和建议策略发到一个 Thread，@ 相关协作方 → 协作方在 Thread 里接着讨论 → 形成待办 → 直接执行策略 | 见下 |

**团队协作这一幕的补充（用户 10/15）**：每个项目都有一个个人助理，带着项目记忆，能在群里组织讨论、回答问题、给出行动建议，并经 MCP 或配好的工具能力去执行。

按代码核对的状态：
- 项目主群和公开 Thread、邀请协作方加入项目，已有；讨论要自己部署本地 Server（预览）。
- 讨论服务里还没有 @ 提醒，也找不到助理参与群聊的代码；这两点按方向写。
- 助理的项目记忆、经能力目录调用各插件的能力，在 main。

**之后的几块**：和别的用法比（问 AI、派给 Agent、用带 AI 的单个工具、在 Work 里）→ 现状与边界（集中讲一次）→ 结尾「工具可以不断长出来，工作不必一次次重来。」

**和 Multica 这类产品的区别**（内部判断用，页面不点名）：它是派单板，你把编码任务派给 Agent；Work 是你自己在做事，合适的能力递到手边，Agent 接着同一份记录做，而且管的是整件工作。
