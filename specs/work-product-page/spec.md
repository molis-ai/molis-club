状态：实现完成，待负责人验收（2026-10-24）。分支 `claude/work-page-restart`，从 `origin/main` 7f7cbde 拉出。上一版（2026-10-16「两种读者、产品全景、四幕与现状」）与这一版之前的六轮方案都在 Git 历史里。

## 目标

负责人对这一页只有两条要求（2026-10-23）：

1. 把 Molis Work 的精髓、亮点和对用户的价值讲清楚：例子尽量少、来自真实的使用场景，直观地介绍核心功能，吸引人一屏一屏看下去；看完知道它是什么、对自己有什么帮助、和别的产品有什么不同。
2. 和官网整体调性一致，传递 Work 的调性：极简、干净、高效、重视人。

## 页面

1. **首屏 · 周一早上**：标签行（工作台 · 开发中）、产品名、开场句、口号、产品介绍原句、「报名首批试用」；右边是项目首页（只报变化）：昨晚到今早发布前检查台、助理、Codex 各做了一件，等你的两件，「你」停在「等你验收」上。
2. **全景 · 一个项目，一张工作台**：一整扇窗（照 Soft Workbench：珍珠灰桌面、白色工作面、标签按插件着色、底栏插件组 / 助理输入框 / 右栏开关），七段依次点亮：一个窗口、插件、右栏、浮条、助理、外部 AI、等你。整段一屏放下：上面是标题和这一段的说明，下面是七段（像章节条，墨线和聚光框同一个节奏滑过去）、「界面示意」和开关。聚光框随段滑动，框外蒙一层；每段一小段编排（光标按开插件表、拖选一句点「记成待办」、助理写回并出操作卡、终端经 MCP 读同一份目标、菜单栏胶囊与等你的清单）。窗口配色浅色 / 深色可切。
3. **一个周末 · 周五晚上的一个想法，周日上线**：画廊（宽屏钉住、滚到哪个时刻换哪个；窄屏点着换），左边是一根竖的时间线（每天一个小标，每个时刻一颗点，走过的那段是墨色，时间只写一次），六个时刻：
   - 周五 22:10 想法丢进来，就是一个项目（从已有资料开始 → 项目建议 → 采用 → 目标、文档、待办、资料，助理给出下一步）
   - 周六 10:00 你的规矩写一次，每个 AI 都照着做（从本机导入角色 → 我的做法 → 助理、Codex、Claude Code 各按一条）
   - 周六 15:20 额度用完了，换谁接着做都行（Claude Code 用量到上限 → 「接着做」：Codex、OpenCode、Pi Agent、Grok Build、Cursor，或在 Coding 里用你自己的 DeepSeek Key → 它读到了做到哪、你上午定过什么；会话列表里前面是 Claude Code、Codex 做的）
   - 周六 23:40 说好的事，改了要你点头（Codex 的决定请求，影响写在选项里；**访客亲手选**同意 / 不同意，结果带到第六个时刻）
   - 周日 11:00 缺个工具，说一句就有（底栏说一句 → 插件创作工作台给方案、写代码、过检查、试跑 → 底栏多一颗 → 你 3/4、Claude Code 4/4，同一份检查记录）
   - 周日 17:30 AI 说做完了，Work 说还差你（收尾未生效，手机上的登录待你验收；**访客亲手点**「验收通过」→ 已完成，固定为交付物）
4. **留在你这儿**：存在你的电脑上（studio-intro 原句）、模型你来挑、Key 是你的、AI 能动什么你说了算。
5. **缘起与现在**：「一开始，我们只是想做一个让自己团队用得更顺的工具。」→「判断归人，执行可以托付。」（原句）→ 开发中（报名首批试用、从源码构建）与已发布 · v0.2.0（看源码）。
