## 3. 模块一　产品全景「先看看它长什么样。」【待确认：第三版方案第 01 节】

- **目标（负责人原意）**：不是让人上手，而是让人对**界面和核心功能**有基本了解，大致知道这是一个什么产品。不放新建项目、安装、设置。
- **形式**（讲解画进画面这一点负责人在第一版就同意了；右边目录列去掉）
  - 第 0 段是**地图**：一张工作台上四处同时圈出并写名字——中间是正在用的插件，底栏是这个项目的插件和助理，右栏放参考，屏幕顶上的菜单栏看进度。
  - 之后每段讲一个核心功能，就在它所在的地方讲：气泡说「这是什么、替你做什么」，不说「请点这里」。圆环圈出要点（不用压暗挖洞），光标好看、点击有反馈。
  - 可以逛：画面上每个地方有小圆点，点了跳到讲那里的一段；不点自己往下放；步骤条显示一共几段、在第几段。
- **内容**
  - 写代码：0 整张工作台 → 1 Goals（目标像一份文档：要得到什么、做成了什么、下一步、还差哪几条要求）已发布 → 2 目标页头的终端（Claude Code、Codex 开在这条目标上、一直属于它）已发布 → 3 决定中心（提议写明影响，等你点头；下游受影响的关系图里看得见）已发布 → 4 收尾（每条要求有依据，要你验收的有你的结论）已发布 → 5 浮条（选中一段报错，下一步在旁边，交出去背景跟着走）开发中 → 6 助理与插件（认得项目、能撤销的卡；插件按需加、⌘K）开发中 → 7 菜单栏（不开窗口也看得到每个目标到哪、谁在等你）已发布。
  - 写文档：0 整张工作台 → 1 Pages（选中一句：放进待办、放进另一节，出处跟着走）→ 2 助理 → 3 Inbox（只放要你处理的，写着为什么进来）→ 4 右栏（网页、文件对着写；那边选中的也能放进稿子）→ 5 待办与目标（都带来源）→ 6 插件（PPT、表格数据、表单……；⌘K）→ 7 「需要你看看」（在助理输入框上方）。写文档这套都标开发中（0.3.0 公开后改已发布）。
- **界面细节以 molis-work main 为准**：没有左侧栏（v0.2.0 才有）；底栏插件切换器；右侧栏标签「讨论 · 浏览器 · 电脑 · 文件」+ 插件侧栏页；底栏右侧常驻只有 Shelf、灵光和侧栏开关；通知并进助理输入框上的「需要你看看」；标题栏有「后台任务」；目标以文档打开（标题、预期结果、当前状态、要求、时间线），终端在页头开关里。
- **代码现状**：第一轮的 `Tour`（`app/(site)/work/tour.tsx`，右侧八段目录）还在，要按上面重做。

## 5. 模块三　为什么是 Molis Work【待确认：第三版方案第 02 节】

- **目标（负责人原意）**：从 Molis Work 的优势视角，讲清楚它解决了哪些用户现在没被解决好的问题；要经得起推敲，**不说只有我们能解决**；写代码那边要结合亮点、和前面的演示场景串起来；加一个协作版本。
- **开头**：工作室介绍原句「AI 已经能够参与许多具体任务，一段完整的工作却仍会在不同工具与会话之间断开。」（负责人让把这句从模块四挪到这里）。写代码那版可以再加一句 molis-work README 的意思：「缺的不是更聪明的模型，而是一份所有 Agent 都能对着记账的项目记录。」【待确认】
- **形式 B**（负责人定的）：「你现在大概这样用」一排卡；点一张展开：左两行（会卡在哪 → Molis Work 接上哪一段），右边是那个场景最后一帧的小图 +「回到这个场景」（滚回模块二并打开那扇窗）；最下一行「老实说」。协作那张排最后、带「开发中」。没有 JS 时全部展开成一列。
- **写代码的亮点**（每个对应一个场景）：A 一份记录、几家 Agent 对着记账（已发布）；B 改题要你点头、下游受影响看得见（已发布）；C「完成了」要对得上（已发布）；D 终端跟着目标走，也能放进 Agent 工具的侧边浏览器（已发布）；E 选中就交出去、背景跟着走（开发中）；F 你、助理和 Agent 用同一套工具，缺的让 AI 做（开发中）；G 重复的事串成流程（开发中）。
- **写代码六种用法**（顺序 = 模块二场景顺序）：一个 Agent 一个会话接一个会话（A+D，回首屏）→ 报错、issue 来了复制进终端（E，回「一条报错」）→ Claude Code、Codex 换着用或隔几天回来（A+B+C，回「周三换成 Codex」）→ 让 Agent 写个一次性脚本（F，回「发版清单」）→ 每天自己盯 issue、分拣、开工（G，回第二组流程）→ 和同事、产品一起（开发中，回第三组）。每行的「卡在哪 / 接上哪一段 / 老实说」见第三版方案。
- **写文档五种用法**：对话 AI 开在旁边、复制进复制出（回「好句子」）→ 周报、进展靠翻聊天和邮件拼（回「周报」）→ 新项目开头资料一大堆（回「新项目第一天」）→ 想要个顺手的流程或小工具（回第二组）→ 和同事一起（开发中，回第三组）。
- **「约定」**（两边共用，放选择器下面）：工作数据保存在本机，使用 AI 时会调用你配置的模型服务（原句）；开源（MIT），用你自己的模型服务，DeepSeek、通义千问、Kimi、MiniMax 等都能接，费用直接付给模型商（新说法，要先进工作室介绍【待确认】）；外部内容只当资料，不会变成给 AI 的指令（安全清单 S-13 核对过）；Agent 能记录、能提议，要换掉约好的结果、放宽要求、替你验收，得你点头。
- **必须改的说法**（调研查出来的，随这一块一起改）：
  - 「改约定、算完成，要你点头；Agent 只能提」说过头：Agent 能直接加要求；收尾只在标了「要你验收」的那条上要你。
  - 依据是 Agent 报的，不说「核验」「证明」「测试通过」。
