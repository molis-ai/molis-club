## 0. Molis Work 自己的事实底线（先读这一节）

仓库：<https://github.com/molis-ai/molis-work>（MIT；2026-08-15 建；10-16 时 5 星；2026-09-15 由 GoalBoard 改名）。

### 版本
- **v0.2.0（2026-09-11，发布时叫 GoalBoard）**：已公开发布，**只有源码**，没有安装包。内容：Goals（目标、完成要求、进展、依据、收尾、决定中心、依赖画布）、Sessions（会话目录、绑在目标上的终端、跨 Runtime 交接）、Feed（RSS / 网页 / YouTube / GitHub / Gmail）、成果基础版、菜单栏「工作胶囊」；Runtime 内置接入 Codex、Claude Code、OpenCode、Pi Agent、Grok Build，其他经 MCP。
- **v0.3.0（10-16 是 GitHub 发布草稿，未公开）**：只有 Apple 芯片（arm64）的 DMG，ad-hoc 签名，**未经 Developer ID 签名和 Apple 公证**；26 个内置插件。说明里的主要变化：统一工作台承载插件内容；助理和 Coding 能接收上下文；Pages 评论线程与材料落点；动作目录统一页面、工作流、Agent 与 MCP 的能力发现和授权。（负责人当天还在重新打包，以最新的发布为准。）
- **升级**：0.3.0 打不开 v0.2.0 的数据（每个库只认当前版本，旧迁移链已删），没有随发行的升级工具（`docs/releases/v0.3.0.md`「兼容与升级」、`docs/releases/CHANGELOG.md`「升级须知」）。
- **Issue 插件是内部工具**：官网和任何对外材料都不能出现，截图、画面里也要避开。

### 写代码这边的机制（核对过协议文档）
- Agent **可以直接**：建目标、定初始结果、**加**要求、写记录与报告、提顾虑。
- **要人决定**：换掉约好的结果，改 / 退 / 放宽要求，去掉「要人验收」，改目标树和依赖。Runtime 没有决定权，不能替自己批准（`docs/runtime.en.md`、`docs/mcp.en.md`）。
- **收尾**：每条现行要求都有依据、要人验收的有人的结论、依赖做完、没有阻塞顾虑，才生效；否则记下但不生效。
- **依据是 Agent 自己报的**。协议原话的意思：报告既不构成用户批准，也不是独立核验（`skills/goal-advance/references/protocol.md`）。Molis Work 不替你跑测试。
- **交接**：用户确认后，把当前目标和必要上下文带到目标 Runtime，开一个**新会话**；不搬对话。
- **不派活**（README：Molis Work does not dispatch work for you）。

### 写文档这边的机制（main 上核对过）
- 数据存本机（每个项目一个 SQLite）。往外发的每一类请求列在 `docs/platform/NETWORK.md`：模型服务、连接器、AnySearch 搜索、TypeSafe 函数、可选的 OAuth 代理 `auth.molis.ai`、插件构建检查发给 npm 的包名等。
- 自带模型：模板里有 DeepSeek、MiniMax、通义千问、Kimi 等（`apps/local-host/src/model-provider-templates.ts`），费用直接付给模型商。助理没配模型不能用。
- 提示注入：记忆、页面标题、选区、Feed 等材料只作为带「不可信」声明的数据交给模型（`docs/system/SECURITY-INVARIANTS.md` S-13，有测试）。
- 情境推荐不提供不可撤回的动作（`packages/kernel/src/contextual.ts`）。
- 待办记着「来源与形成原因」（`plugins/native/todo/src/actions.ts`），从选区、Inbox、灵光、助理建的待办都带来源。
- 工作流程四种交接：模板转换 / AI 整理后 / 人看完后 / 判断后（`plugins/native/workflows/src/model.ts`）。「最多 12 站」没在代码里找到，不要用这个数字。
- 新建项目：「从一个真实项目开始」「带入材料新建」（`apps/workbench/src/arrival/chooser.ts`）。
- 外部 MCP 客户端按动作、版本、范围逐项授权，撤权下一次调用生效（`docs/mcp.en.md`）。

### 还没有的
- 人和人的协作（群里 @、助理进群、群里讨论成目标）：依赖服务端，正在开发，团队接下来就要用 Work 协作。
- 多设备、手机、团队空间、插件分享。
- Windows / Linux 桌面（v0.2.0 的网页工作台在其他系统上可以前台启动）。

## 2. 写代码的人

### 2.1 大家现在怎么用 Agent
1. **一个 Agent、一次一个会话是绝大多数**：Stack Overflow 2026-05 脉搏调查（n≈1,100），69% 只用一个 Agent，68% 更喜欢可预期的单 Agent，63% 很少或从不放手自动跑。用多 Agent 的约三分之一，但他们是最活跃的每天用户。[核] <https://stackoverflow.blog/2026/05/27/agents-on-a-leash-agentic-ai-remains-mostly-monitored-at-work>（文中工具占比和图表数字不一致，引用要小心）
2. **几家混用**：Stack Overflow 2026 调查，Agent 用户里 Claude Code 66%、Copilot 59%（多选，至少 25% 两个都用）；27% 的组织「不同的活用不同的模型」。[核] <https://survey.stackoverflow.co/2026/ai>
3. **先规格后执行**：spec-kit 约 14.1 万星、OpenSpec 7.2 万、BMAD 5.4 万 [核]；Claude Code 官方最佳实践是「采访 → 写 SPEC.md → 开新会话」[核] <https://code.claude.com/docs/en/best-practices>
4. **并行本地 Agent（worktree）**：Willison「同时跑 Claude Code 和 Codex CLI」（2025-10-05）[核]；Faros：重度采用的团队 PR 审查时间 +91%（厂商数据，相关不等于因果）[核] <https://www.faros.ai/blog/ai-software-engineering>
5. **云端 Agent 从 issue 出 PR**：Copilot coding agent 2025 年 5–9 月超过 100 万个 PR（Octoverse）[核]
6. **长时间自动循环**：Ralph 循环、Claude `/goal`、Codex Goals [核]

### 2.3 同类
- **最像的：Traycer Desktop**（MIT，约 1.6k 星，v1.5.1 2026-10-10）[核] <https://docs.traycer.ai/>。Claude Code、Codex、Cursor 等并行跑；任务里放 Agent、文件、终端和比对话活得久的规格、工单、评审；Agent 能互相读对话；限额时可自动换账号或模型（默认关）；**要登录账号，任务同步到云**；个人免费、团队同步每人每月 20 美元。完成由评审 Agent 判，skill 可被跳过，人不强制验收。
- **厂商的 goal**：Claude Code `/goal`（单会话完成条件，小模型每轮读对话判断，不读文件不跑命令）[核] <https://code.claude.com/docs/en/goal.md>；Codex Goals（2026-05-21 GA，线程内的完成合同，模型对着证据自判）[核] <https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex>。**开发者一听「目标」会以为是这个**。
- **并行桌面**：Conductor 0.91（Mac，worktree，工作区里有 `.context` 目录，待办没勾完不让合）[核]；Superset 1.38（ELv2，20 多家 Agent，换 Agent 时带最后 36,000 字对话）[核]；Emdash、Claude Squad、Nimbalyst、Agent of Empires [核]；Vibe Kanban 公司 2026-04 关闭、转社区维护 [核]；Terragon 2026-02 停服 [核]；Crystal 弃用 [核]。共同点：隔离、并行、看 diff、PR、通知做得好；单位是工作区 / 分支 / 会话，没有长期的目标记录。
- **厂商平台**：Warp、Zed（ACP）、Devin Desktop、GitHub Agent HQ 能「托管」别家 Agent，只是跑在窗格里看状态，不共享任务和计划 [核]；各家都有自己的「项目层」（Cursor Projects、Claude Code Projects、Codex Goals、Devin Spaces、Factory Missions），都只在自家 [核]。Factory Missions 每个里程碑末尾有验证阶段，QA 报告能设成必过检查——是「机器核对完成」做得最强的 [核]。
- **规格与任务**：文件在仓库里，天然跨厂商、能走 git 评审，**这正是「跨厂商共享」本身不算优势的原因**。没有一家在动作层拦住 Agent 改要求或替自己批准；Beads 有 human gate 但 `--force` 能绕 [核]；Backlog.md 的「全部勾完才能 Done」是提示词规则 [核]。
- **结论（推断）**：没有一家同时做到「几家共享任务记录 + 一条条完成要求 + 收尾看依据 + 改要求只能提、人批」，各家最多占两样。

### 2.4 能说 / 不能说
- 能说：同一份目标记录，五家内置 + MCP 读写；本机保存、不用账号；目标比任何一次会话活得久；Agent 能记录和提议，不能悄悄换掉约好的结果、放宽要求、替你验收；收尾在缺依据、缺你的验收、依赖没完、有阻塞顾虑时不生效；终端绑在目标上，菜单栏看进度。
- 不能说：核验 / 证明做完 / 测试通过；Agent 只能提；只有我们能让几家共享；编排 / 并行派活；无缝接着对话；把未发布的说成已发布；Windows / Linux 桌面；用户量；平滑升级。

## 3. 写文档、管事情的人

### 3.1 大家现在怎么用 AI
1. **对话框开在旁边，复制进、复制出**：ChatGPT 工作消息里写作约四成，其中约三分之二是改用户自己给的字 [核] <https://www.nber.org/papers/w34255>；企业 AI 用户 77% 往对话框贴数据，其中 82% 来自个人账号 [核]（LayerX，经 The Register）；Menlo 2026：写作是第一用途（61%）[核] <https://menlovc.com/perspective/2026-the-state-of-consumer-ai/>
2. **办公套件里的 AI**：2026 年各家都在文档里直接改、带批准卡——Word 的 Agent 模式成默认（2026-04-22）、Claude 进 Google 文档（2026-10-06 beta）、ChatGPT 进 Word（2026-09-17）、WPS 灵犀、飞书 8.0 [核]。国内办公 AI 往 PC 客户端走，PC 端同比 +340.6% [核]（QuestMobile）
3. **轮流用三个左右的 AI，按事情挑**：每人约 3.0 个（2025 年 2.2）[核]（Menlo 2026）；国内「按场景切换」，深度用户近两成用五个以上 [核] <https://www.questmobile.com.cn/research/report/2109848735332814849>。**没有证据显示有人在同一份工作里换着用**；真实需求是别被一家锁住：Claude、Gemini 都在 2026-03 做了「从别家导入记忆」[核]
4. **读资料、做笔记、要出处**：NotebookLM 一类、Heptabase、ima、秘塔、Readwise、Granola
5. **交给 Agent 和自动化：少数**：微软 2026 工作趋势「前沿」用户 16% [核]；Glide 的厂商调查：55% 用 Agent 的企业找顾问做 [核]

### 3.3 同类（最该盯的在前）
- **Raycast**（Mac 上重合最多）：2.2 起支持 Ollama、OpenRouter、自定义兼容接口；2.3 有能规划、用扩展的 Agent、带记忆的 Projects、定时自动化、「自带订阅」（Claude、ChatGPT 账号）；能「把当前窗口 / 元素发给 AI」；Pro 每月 10 美元 [核] <https://www.raycast.com/changelog>
- **Reflect Open**（理念最像）：2026-07-14，MIT，本地 Markdown，iCloud / Git 同步，自带 key，带引用回答，选中改写，私密笔记不发给 AI，Mac 免费 [核] <https://reflect.app/blog/reflect-open>
- **Claude Cowork 与 Google 文档插件**：处理在 Anthropic 服务器上；永久删除前会问但没有撤销；文档插件看得见选区、有批准卡 [核]
- **Notion 3.8**（2026-10-13）：150+ MCP 连接、自己的 MCP 服务、带署名的版本历史、ChatGPT 订阅可付 Notion AI（商业版以上）[核]

### 3.4 结论
- 「AI 在你真实的东西上动手、要你批准」在 2026 年是标配，不是卖点。
- 还空着的是四样凑在一起：数据存本机且公开列出每类外发请求；自带模型（含国产）不加价；一套动作给界面、助理、流程和外部 Agent 共用并逐项授权；选中一句送到**另一个**工具并带着出处。
- 写文档的人「同一页换 AI 接着写」不是需求，改成「你的资料、出处和历史在你的 Mac 上，今天和明年用哪家 AI 都接得上」。
- 这群人最大的门槛是**装得上**：没有公开的签名安装包，仓库说明面向写代码的人，还要自己去申请 API key。

### 3.5 能说 / 不能说
- 能说：存本机、开源 MIT；自带模型（列出支持的几家）；外部客户端逐个动作授权；选中送到别的插件、待办带来源；助理动作是卡、可撤销（限可撤回的）；外部内容只当资料。
- 不能说：在 Mac 上任何地方选中（那是 Molis Tool，未发布）；数据不出本机 / 私密 AI；本地模型、离线；用 Claude 订阅（Anthropic 不允许第三方助理这样用 [核] <https://code.claude.com/docs/en/legal-and-compliance>）；AI 做的插件「安全」；团队协作；比 Notion / Copilot / 飞书更好；现在下载 / 免费。

## 4. 给产品的想法（按「能和别人拉开距离」排）

### 写代码
1. **依据分三档**：Agent 自报 / 机器核过 / 人验收。要求能绑一条检查（命令、CI 结果、PR 合并且检查通过），由 Molis Work 自己跑或读。做成后从「记账」变「核账」，和厂商 goal（只看对话判断）拉开。
2. **做厂商 goal 的上一层**：从目标里没完成的要求生成 Claude `/goal` 条件或 Codex Goal，跑完把结论收回来当报告。
3. **和仓库规格互通**：导入导出 spec-kit、OpenSpec、Backlog.md、Beads；提交和 PR 当依据。
4. **升级路径**：「事实来源」打不开自己的旧库，伤说服力。
5. **「需要你」的提醒**：菜单栏角标、系统通知。
6. **和并行工具一起用**：给 Conductor、Superset、Traycer 的接入片段；显示哪个工作区在做哪个目标。
7. **云端 Agent 够不到本机 MCP**：远程 MCP 桥或 GitHub issue 同步。
8. 量一下 35+ 个 Runtime 工具描述的 token 开销（Taskmaster 被抱怨过同样的问题）。

### 写文档
1. **先装得上**：签名公证的安装包；第一次打开不需要终端；面向不写代码的人的说明。
2. **用 ChatGPT 账号登录用量**：OpenAI 2026-09-29 起允许开源本机客户端用 Plus / Pro 额度，不用审批（预览限额），要接 Responses 接口 [核] <https://developers.openai.com/siwc/quickstart>。
3. **每个动作花了多少**（token、钱）。
4. **出处一路跟到底**：改过之后、到 PPT 里还在；AI 写的段落标出来（Heptabase 的「Created by AI」）。
5. **文件能读**：Pages 镜像成 Markdown，能导出 Word、飞书文档。
6. **macOS App Intents / 服务菜单**：从 Spotlight、快捷指令、Siri 调「放进待办」「放进稿子」；也是通往 Molis Tool 的桥。
7. **提示注入的出站闸**：读过不可信内容的会话里，发邮件、MCP 写入一律先批。
8. **本地模型模板**（Ollama、LM Studio），并标出哪些功能会外发。
9. **国内**：写回飞书 / 钉钉 / WPS；导入公众号文章；默认 DeepSeek 或通义千问。
10. **手机上随手收**（灵光、Inbox）。

## 8. 下一步：要给产品迭代做输入，还需要调研什么

每项写清：要回答的问题 → 为什么对产品重要 → 怎么查 → 交付什么。

### 8.1 用户访谈与小问卷（最缺，优先）
- **问题**：两类人里，谁是第一批真会装、会留下来的？他们每周在哪几步最痛？愿不愿意自己配模型服务？
- **为什么**：这次全是二手资料；「依据三档」「ChatGPT 登录」「出处到底」这些想法要先有人点头才值得做。
- **怎么查**：写代码 8–12 人（每天用 Claude Code / Codex，分「单 Agent」和「几家混用 / 并行」两组），写文档 8–12 人（研究、内容、运营、创业者，国内外各半）；半结构访谈 45 分钟 + 让对方屏幕共享走一遍上周真实的一件事；再发一份 10 题问卷扩大样本。
- **交付**：每人一页卡片（现在的做法、卡点原话、对 Molis Work 每个亮点的反应）；痛点 × 人群的频次表；「会不会装 0.3.0」的意向。

### 8.2 亲手装、亲手用对手
- **问题**：最近的几个对手，从下载到第一次得到价值要几步、几分钟？它们怎么处理「做完」「批准」「出处」「撤销」？
- **对象**：Traycer、Conductor、Superset（写代码）；Raycast、Reflect Open、Claude Cowork 与 Google 文档插件、Notion 3.8、腾讯 WorkBuddy（写文档）。
- **怎么查**：同一个任务各走一遍（例如「修一个 bug 并说明为什么算修好」「把一段视频里的一句话放进稿子、记一条待办」），录屏、计时、截关键界面。
- **交付**：每个产品一页（首次价值时间、关键界面截图、做得好的细节、我们可以借的）；一张横向对照表。

### 8.3 「做完」怎么被核对（给「依据三档」做设计输入）
- **问题**：机器核对完成，别人怎么做？绑什么（命令、CI、PR、截图录屏）？谁来跑？失败了怎么回到人手里？
- **对象**：Factory Missions 验证阶段与 QA 必过检查、Devin 测试录屏、Claude Code `TaskCompleted` 钩子、Codex Goals、Kiro 属性测试、Beads gate、Conductor Checks。
- **交付**：机制对照表 + 三档依据的界面与协议草案（哪些能自动跑、哪些只能人看）。

### 8.4 团队协作（马上要做的功能）
- **问题**：团队里人和 Agent 一起干活，别人怎么组织？讨论、任务、Agent 产出在哪里汇合？谁能批？
- **对象**：Linear agents 与 agent sessions、Slack / 飞书 / 钉钉里的 Agent、Notion 协作 + Agent、Amp 的 multiplayer 与线程分享、Claude Code Projects、Devin Spaces、GitHub Agent HQ。
- **交付**：协作模型对照（权限、通知、可见性、批准链）；我们「群里讨论成目标 → Agent 接手 → 进展回群」的差异点与风险。

### 8.5 社区里的真实抱怨（系统梳理）
- **问题**：用户自己的话里，哪些痛点最高频？
- **来源**：Reddit（r/ClaudeAI、r/ChatGPTCoding、r/cursor、r/ObsidianMD、r/Notion）、Hacker News、GitHub issue；国内 V2EX、即刻、少数派、知乎、小红书。
- **交付**：按痛点归类的原话摘录（每条带链接和日期），频次排序。

### 8.6 装得上：分发与第一次打开
- **问题**：Mac 应用怎样做到「不懂终端也能装」？公证、自动更新、第一次打开不要终端；不填 API key 能不能先用起来？
- **对象**：Apple 公证流程与成本、Sparkle 等自动更新、OpenAI「Sign in with ChatGPT」细节（额度、限流、Responses 接口）、其他开源 Mac 应用的首次体验（Reflect Open、Craft Agents、Anytype）。
- **交付**：最短可行的首次体验流程图 + 要做的工程清单。

### 8.7 国内市场
- **问题**：国内写文档的人要不要本机 + 自带模型？要写回哪里？合规上有什么坑？
- **对象**：飞书 / 钉钉 / WPS 的开放能力（MCP、写回文档）、公众号文章导入、国产模型接入体验与价格、数据出境与备案要求、WorkBuddy 的真实评价。
- **交付**：国内首批用户画像与必须有的三个接入。

### 8.8 价格与商业模式
- **问题**：自带模型之外，我们靠什么收钱？用户能接受什么？
- **对象**：Raycast、Notion、Craft、Reflect、Obsidian（同步 / 发布收费）、Traycer（团队同步收费）、Conductor（Pro / Teams）、WorkBuddy。
- **交付**：同类定价表 + 两三种可选模式及风险。

### 8.9 提示注入与「致命三角」
- **问题**：读了外部内容的 Agent 要发邮件、写别处，别人怎么设闸？
- **对象**：Simon Willison 的文章与案例、Anthropic / OpenAI 的防护说明、Copilot / Cowork 的批准设计、钉钉悟空的快照回滚。
- **交付**：Molis Work 出站动作的闸门规则草案。
