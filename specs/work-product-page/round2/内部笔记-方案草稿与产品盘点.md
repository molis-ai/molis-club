## 模块二：三组场景（不再出现 递 / 接 / 长 / 一起干 / 想怎么干 当标题）

组 1「一件事，从你手里到做完」——你 + 几个 AI，同一件事（原 递 → 接 → 长）
- dev
  - 一条报错进来，选中就交给 Codex（递，开发中）
    - 交互：画面里亮着的报错，点一下选中；浮条亮出「交给 Codex」，点它
  - 周三换成 Codex，它知道做到哪了（接，已发布 v0.2.0）
    - 交互：Codex 提议改约定，卡片「等你确认」，点「同意」；说做完了→收尾没成立，点「看还差什么」
  - 发版前缺个清单，让 AI 现做一个（长，开发中）
    - 交互：点提示词「做个发版清单」；做好后底栏多一个图标，点它
- doc
  - 看到一句好话，直接放进稿子（递）
  - 换个 AI，接着写第三部分（接）
  - 缺个选题库，让 AI 做一个（长）

组 2「按你的方式，拼一张自己的工作台」——自定义插件 + 跨插件工作流（原 想怎么干）
- 选一种干法（独立开发 / 开源维护 / 技术写作 | 自媒体 / 创业分析 / 写研究），点「跑一遍」看一件事沿线走
- 「你自己的」：把组 1 里刚做的发版清单 / 选题库拼进来（前后呼应）

组 3「和别人一起，也接得上」——协作（原 一起干，开发中，放最后当「接下来」）
- dev：用户一句抱怨，到修好上线（点「同意」）
- doc：一个决定，牵动的事都跟上（点「选 B」）

形式：每个场景一个可交互的窗口，讲解画在窗口里（气泡 + 步骤点），亮着的地方可以点，不点也会自己演；场景之间用一排卡片切换，不用滚好几屏。

## 模块三：为什么是 Molis Work

形式候选
- A 同一件事两种过法（左右两条时间线）
- B 「你现在大概这样用」选择器（推荐）：选你现在的用法 → 你会卡在哪 → Molis Work 怎么接上（不是换掉）
- C 表格（现状，偏干）

dev 的四种常见用法
1. 终端里一个 Agent + 规则文件 / 交接文档：每开新会话重讲背景；进度靠交接文件，靠 Agent 自觉写
2. IDE 里的 Agent：上下文只在代码和这段对话里；为什么改、做到哪不留
3. 把 issue 派给云端 Agent：只认 issue 里写的；结果是一个 PR，凭什么算完要你自己核
4. 几个 Agent 并行：彼此不知道对方在等什么；改了约定没人告诉另一边
→ Molis Work：同一组目标是所有 Agent 的记录（要求、依赖、进展、依据）；改约定先提议，你点头；说做完要有依据；菜单栏一眼看进度。接上 Claude Code、Codex，而不是换掉它们。
不如它们的：写代码本身编码 Agent 更强；只支持 macOS；从源码装；团队、多设备还没有。

doc 的四种常见用法
1. 和对话 AI 聊：传资料、交代背景；结果在对话里，复制回文档；换个 AI 再来一遍；出处丢了
2. 文档工具里的 AI：AI 只在那一个工具里；视频、邮件、网页得先搬进来
3. 自动化工具：先画流程、连账号；流程不知道你此刻在写什么
4. 一句话做个小应用：做出来是孤岛，不认识你的文档和待办
→ Molis Work：AI 在你真实的工具里动手；资料带出处落进该在的地方；换个 AI 接着同一页；缺的工具让 AI 做，装进同一张工作台，助理和 Agent 也用得上。
不如它们的：新版没有安装包；多人编辑、多设备还没有；只支持 macOS；插件创作是预览。
