01同类网站调研

看了 37 个页面，挑出 28 个值得借的地方。

按你关心的五件事分组：首屏、上手教程、场景、为什么选它、下载页。截图都是今天在 1440 宽下截的。

A　首屏：右边放什么

  • 右边越来越少放整张截图，多是一个真实的瞬间（Granola 的笔记自己往下写）或产品本身就能点（Cal.com 的日历能直接选日子）。
  • 讲 Agent 的产品，把「几个 Agent 同时在干」画成一排小窗或一张任务格（Linear Agents、Warp 的 fig. 1、Superset 的终端标签），比一个大窗口好懂。
  • 主按钮几乎都是「Download for Mac」，下面一行写系统要求（Raycast、Granola、Claude Code）。Molis Work 首屏现在没有主按钮。
  • 和白房子气质最近的是 Granola、Cal.com、Tana：暖白底、字在左、右边一块很安静的东西。

B　上手教程：讲解怎么放进画面

  • 讲解和画面同步有三种做法：Things 的「步骤卡 + ▶ Play」、Zed 的手风琴（展开哪条演哪条）、Amp 的章节时间码。都能自己点、能重播。
  • 光标和点击：Screen Studio 讲得最细——光标慢慢滑过去、每次点击一圈淡淡的环、自动推近到点的地方、闲着时光标藏起来。
  • 高亮目标：Notion 用一圈杏色圆角细环圈住目标，不把整屏压暗。我们现在的聚光把字切成半行，就是因为用了「压暗 + 抠一个矩形」。

C　场景：让人愿意点

  • 场景用一排小标签切换，点了清空重演（Raycast 有十个场景小标签：修 bug、看 PR、清收件箱……开发和日常的混在一起，两类人都找得到自己的）。
  • 邀请点击：Cal.com 不写「点这里」，让真实的控件自己邀请；Claude Cowork 用一句铅笔小注加一根手绘箭头「hover 试试」。
  • 按身份切换：mymind 一排纯文字的身份标签，选中的变强调色、下面换一句标题——和我们「写代码 / 写文档、管事情」是同一件事。

Claude Cowork（claude.com/product/cowork）的「Power through tedious tasks」一段也值得看：场景标签下一句铅笔小注和手绘箭头，引导去点。无头浏览器截不到它，只核对了文字。

D　为什么选它：从人现在怎么做讲起

  • 从「变化」开头，不从对手开头：Linear 的 Switch 页先说「AI 让每个人写得更快，协作反而成了瓶颈」。
  • 痛点 → 解法成组出现（Sunsama 三个痛点对三个答案）；同一件事前后对照（iA Writer 把 Word 和专注模式摆在一起，Basecamp 的 Before / After）。
  • 工作室自己的声音：HEY 有一封创始人信；mymind 写了一串「我们承诺不做」。
  • 把别的 Agent 当客人：Zed、Amp 都直接说「能接你在用的 Claude、Codex」。我们也是这样——接上，不替代。

F　下载页

  • 下载页都很短：一个大按钮、版本号、系统要求、其他安装方式、发布记录链接。
  • Ghostty 把「从源码构建」列成正式选项之一——正好是我们今天的情况。
  • Granola 下载后给三张图讲安装：打开 dmg → 拖进「应用程序」→ 打开。等我们有安装包时可以照做。

03模块一　这是什么

首屏：字回到左边，右边只放一件事。

左边按你说的放产品名和介绍，从上到下：作品标签（Molis Work · 工作台 · 开源开发中）→ 大字 Molis Work → 标题「让工作，在人、工具与 AI 之间继续」→ 一句「一张可以按需要组合工具…的工作台」→ 主按钮「在 Mac 上用」、次按钮「看它怎么用」 → 一行小字「macOS · 开源 · 现在从源码安装」。「你主要做什么？」的切换挪到页内顶栏和三分钟上手的标题旁边，首屏不放。

右边四个方向：

A　一个真实的瞬间（Granola、Claude Code）
一扇安静的窗，8–10 秒只演一件事：写代码看「选中报错 → 交给 Codex → 结果回到这页」，写文档看「选中一句 → 放进稿子，带着出处」。就是现在的首屏，去掉多余的窗口细节、修好浮条压字。演的是浮条，标「开发中」。

B　你来点第一下（Cal.com）
不是整扇窗，是一张纸片：一句话轻轻呼吸着「选中试试」，访客一点，浮条递来三个动作，再点一个，结果落进下方的一张小卡。首屏本身就是上手第一步。好玩，但演的同样是开发中的浮条。

C　同一页，几个人在写 推荐（Linear Agents、Kiro）
右边是一页目标，像一张纸：三条要求、下面一条时间线，Claude Code、Codex 和你轮流写进同一页；Codex 提议改约定，卡片「等你确认」；说做完了，还差一条依据。演的全是 v0.2.0 已发布的能力，可以标「已发布」，最诚实，也最能说明它和别的工具不一样的地方。写文档那一版是同一页稿子：你、助理、另一个 AI 各写一段，都带出处（开发中）。

D　你的工具都在这一张台上（Attio）
中间一扇工作台，四周浮着一张终端会话卡、一条 Inbox、一条目标依据、一份成果；Agent 碰到哪件，哪件亮起来。最像「平台」，信息量也最大，第一眼可能看不过来。

我的建议：C。第一屏最要紧的是「这是什么、和我有什么关系」。C 把产品的脊梁——你和几个 AI 接着同一份记录做，做没做完可以核对——直接画成一张纸，而且是今天就能用的部分，信任感最强；视觉上也最像白房子里的一件展品。B 的「亲手点一下」放到三分钟上手的第一步。如果你更想要动感，就选 A。

参照：Granola、Cal.com、Claude Code、Linear for Agents、Kiro（见第 01 节 A、D 组）。

04模块二　对你有什么用

三组场景，一个场景一扇能点的窗。

不再用「递、接、长、一起干、想怎么干」做标题，改成读者自己的处境。三组的逻辑：先是你和几个 AI 把一件事做完（原来的递 → 接 → 长），再是把工作台拼成你的样子（原来的想怎么干），最后是和别人一起（原来的一起干）。

第一组一件事，从你手里到做完

你 + 几个 AI，同一件事：交出去 → 换人接着做 → 缺工具就现做

第二组按你的方式，拼一张自己的工作台

插件串成你的干法；第一组里现做的工具也拼得进来，前后呼应

第三组 · 接下来和别人一起，也接得上

标「开发中」，全演；「我们团队接下来就用它协作」

顺序我建议这样排：协作还在开发中，放最后当「接下来」，收得更自然。你原来列的是「一起干」在「想怎么干」前面，如果你更想先讲协作，二、三组对调即可。

05模块三　为什么是 Molis Work（先对方案）

不从对手讲起，从你现在怎么用 AI 讲起。

开头一句讲变化（借 Linear）：AI 已经能做很多具体的事，一段完整的工作却还在不同工具、不同会话之间断开。然后按读者讲。展示形式三选一：

形式 A同一件事，两种过法：左边「现在」一条时间线，右边「在 Molis Work 里」一条，步数和搬运次数一眼可比（借 iA Writer、Basecamp）。
形式 B 推荐「你现在大概这样用」：读者点选自己现在的用法，下面亮出「会卡在哪」和「Molis Work 怎么接上」。代入感最强，也最能说明我们是接上，不是换掉。
形式 C表格：做法、你要做的、结果在哪、下次接着做。就是现在的写法，信息全但偏干。

写代码的人：四种常见用法

你现在大概这样用会卡在哪Molis Work 怎么接上
终端里开一个 Agent
加规则文件、交接文档		每开一个新会话都要重讲背景；进度靠交接文件，靠 Agent 自觉写目标、要求、进展记在同一组目标上，新会话一句「接着做」就读到

06模块四　我们为什么做 Molis Work

用工作室介绍里的原句，讲一段我们自己的话。

从上到下（引号里都是工作室介绍的原句，不改写）：

AI 已经能够参与许多具体任务，一段完整的工作却仍会在不同工具与会话之间断开。Molis Work 由此关注工作怎样持续进行。
我们希望这种协作是连续的：你能看见 AI 动了什么，也能随时亲自接手；需要你判断的事情，会清楚地交回你手里。
想要什么、为什么做、什么结果值得接受，这些重要判断留在人手里。

接着是「事情都顺了，那人做什么？」：保留 9:00–18:00 那条时间条（杂事变薄，空出来的时间给「去够更难的问题、去创造、留给生活」），三栏例子按身份换。最后一行大字「技术，回到人的尺度。」，两个去处：读《人的尺度》、认识我们（关于页）。落款「始终好奇，持续创造。」。不放海边照片。

要你定：时间条留不留。留，是因为它本身就是一段演示，把「那人做什么」画出来；不留，这一段会更短、更像一封信。
