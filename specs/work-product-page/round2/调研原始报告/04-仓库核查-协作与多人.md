## 报告

Multi-person collaboration in Molis Work: what exists and how real it is (read-only; repo root R = .../scratchpad/molis-work-src/repo)

**Bottom line:** Main has a real group-chat code path and a working server. But the desktop product only lets loopback clients in, and it never wires up the member-invite path. So in the shipped workbench the 讨论 tab is effectively a one-person chat. Inviting other people only works through a standalone, hand-run Node launcher (CLI, JSON config, your own LAN HTTPS certificate). There is no team, sync, cloud, account or relay feature. All of the chat and server code landed after v0.2.0 and is unreleased.

**Timing.** v0.2.0 (2026-09-11) is the root commit, and its tree has no `server/`, `packages/im-ui` or `apps/server`. Server, identity and IM first landed in `5f10629d` on 2026-09-26 ("feat(server): 跨端接续、团队协作与群聊"). The 讨论 split view came in `01a1961a` (09-27) and moved into the platform side panel on 09-30. The Home-data registration of `server/server.sqlite` is `f7c8fa62` (10-09). There is no tag after v0.2.0.

**1. 讨论 tab (group chat, threads, invites). Status: implemented on main, but loopback-only in the product.**
- **What it is:** one main group per project, plus public Threads, quotes, search and read positions. The schema in `R/server/src/im/schema.ts` has `im_rooms` (with `invite_token`), `im_members`, `im_threads`, `im_messages`, `im_receipts` and `im_read_positions`. There is no DM table.
- **No direct messages:** `R/packages/im-ui/README.md:6` says "不提供私聊".
- **Desktop mount:** `R/apps/local-host/src/im-server.ts:43-49` rejects any request whose Host header is not loopback ("群聊服务地址不匹配", 403). The side panel loads it as an iframe at `/im?embedded=1` (`R/apps/workbench/src/side-panel.ts:45,127`). The store is `{home}/server/server.sqlite` (`im-server.ts:98`); there is no `server.sqlite` in the repo itself.
- **Invites:** non-project rooms get a `randomBytes(24)` token and a link of the form `${origin}/im?invite=…` (`R/server/src/im/writes.ts:79,132`). In the desktop that origin is loopback, so the link is useless to anyone else.
  - Project rooms refuse invite links: "成员由项目权限统一管理" (`writes.ts:72`) and "请通过项目邀请加入讨论" (`writes.ts:61`).
  - The invite button is hidden for project rooms (`R/packages/im-ui/src/views.ts:41`).
  - Project members come from `mw_access`, which only the `/continuity` invite routes fill (`R/server/src/http.ts:94-103`, `R/server/src/identity.ts:82-87`). The desktop doesn't mount those routes, and nothing in `apps/workbench` or `apps/local-host` references `/continuity`.
- **AI in the chat:** none. There are no agent or assistant references in `server/src/im` or `im-ui`. `im-ui/README.md:45` lists file upload, mention notifications, edit/delete and "AI 总结" as "尚未实现". It adds that cross-device flows are not accepted and the chat "不能据此宣称完整通信产品或可发布".
- **Network service:** `R/server` (core library, maturity `partial`) plus `R/apps/server` (a private, headless launcher run with `node apps/server/dist/main.js serve …`).
  - It binds loopback by default. LAN use needs an explicit `--hostname`/`--origin`/`--cert`/`--key` with a certificate the phone trusts.
  - `server/README.md` says "没有购买服务、公开部署或接入私人账号" and that browser checks are "不等于真机手机验收".
  - The one-time code in `connect.json` lasts 10 minutes. Project invites carry viewer/editor roles. Phones can only record Goal progress.
  - There is no relay or public deployment: BL-063 "群聊：手机真机与公网部署" is marked 明确后续做 (`R/specs/BACKLOG.md:121`).
  - Tests exist: `R/tests/im-*.test.ts` and `R/tests/cross-device-*.test.ts`.

It is consumed by `apps/local-host` and has existed since v0.2.0.
- **`docs/modules/identity-team-access.md`: docs only.** Line 11 says "无实现，也没有包（占位包已删除）；Team/Server 产品行为需要未来独立 Spec".
- **`docs/modules/sync-replication.md`: docs only.** Line 11 says "无实现，也没有包 … 真正同步功能需要未来独立 Spec".
- **Backlog:** BL-071 "团队空间与多人共享项目" is 未开始 (`BACKLOG.md:130`). BL-022 (team-shared memory) waits on collaboration being settled (`:48`).

**4. Sharing, publishing, cloud, accounts, login**
- **"Who you are" in the project menu: a hardcoded placeholder.** `R/apps/workbench/src/settings-directory.ts:45` renders the literal name `L("一骏")` with `L("本地空间")`. The comment at :38-39 says it is "shown, not offered as a control until there is an account page".
- **W3-09-AUTH is not user login.** It is a set of tests that refuse an AI tool action after its permission is withdrawn mid-call (`R/specs/repository-anti-corruption/spec.md:1912-1914`, `R/tests/action-authority-tail.test.ts`).
- **The only cloud piece is an OAuth broker for connectors.** `R/apps/local-host/cloudflare/README.md` describes a worker at `https://auth.molis.ai` that exchanges OAuth codes for third-party connectors and "does not read user content or persist tokens". Real provider grants are still pending, and it is not an account system.
- `R/PRODUCT.md:151` says V1 excludes "云端多租户、复杂权限系统".
- **Form "publish" is local only.** It "只保存本机状态和稳定 `share_id`，不产生外网填写链接" (`R/plugins/native/form/README.md:13`), and hosted collection is out of scope (:28).
- **Pages comments are local.** They are stored in `page_comments`; `@助理` gets an AI reply. There is no other person involved (`R/plugins/native/pages/README.md:7`).

**5. Collecting feedback from end users or customers: none found.**
- There is no feedback or telemetry endpoint. The `sentry` hits are a connector for reading the user's own Sentry account.
- The Feed module (`R/modules/feed`) handles items from external info sources (RSS and connectors), not customer feedback.
- The Form plugin could collect survey answers, but only by local fill-in or by importing answer files ("答卷出自对方的文件", README:36). There is no hosted link.
- The Issues plugin (`R/plugins/native/issues`) is the personal bug-capture tool, as you noted.
