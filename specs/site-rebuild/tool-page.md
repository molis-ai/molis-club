# Molis Tool 产品页重做：一面白墙

2026-10-15。负责人要求：以 Folio 版 Tool 页（`/demos/brand/folio/tool`）为底，参照之前「逐页分镜」的可视化做法，按现在官网的基调重新审视 Tool 产品页；介绍短一点，控制在 5 屏。2026-10-16 负责人看过第一版五屏方案后，同意按「一面白墙」试做；本文按已做出的样子写，第一版方案的差别见第 7 节。

## 0. 依据

- **实看**：1440×900 逐屏截图。新站 `/tool` 页面高 9658px，约 10.7 屏；Folio 版约 10.4 屏。
- **文案**：`docs/studio-intro.md` 4.2、第 3 章、附录 A（DropAgent 与牛来那段）。
- **产品事实**：molis-tool 仓库的设计纲领（2026-09-28）、路线图与 README（2026-10-07）。
- **做法**：`spec.md` 5.1 / 5.2；「逐页分镜」（visual-story 分支的 `visual-storyboard.md`，尚未合进 main）：一拍只讲一件事，先画面后文字，原文收进「展开看原文」，当前进展用「已有 / 还没有」块。
- **基调**：main 上最新的首页（天空、海边、美术馆午后）、企业合作（问题卡、四站路线、卡片压在照片一角）、社区（粗墨线小家伙、作品连着做法）。各页调性不同，骨架一致。

## 1. 现在的问题

### 新站 `/tool`

1. **首屏看不出它做什么。** 右边只有一张白墙天光，「选中这一页的任意一句话试试」是一枚小虚线签，几乎没人会注意。Folio 版最被认可的，正是首屏右边那段贴合产品的动效；新站把它丢了。
2. **演示区框大、内容小。** 16:10 的白框里常常只有一行 14px 的字；左栏每一步之间隔着近半屏空白，只剩一道细线和一行「c 一步做完，结果留在原处」。这不是留白，是空洞。
3. **老路四步没有力道。** 开场只是四枚小胶囊，看不出老路有多绕、一步有多近。
4. **「一个下午」只活在时间戳里。** 下午 2:10 / 2:40 / 3:15 / 4:30 写在小字里，画面里感觉不到时间在走。
5. **标志性交互埋得太深。** 「选中任意一句话」在第 7 屏之后才正式出现，样子像一个表单（示例句 + 「选中这句话」）。
6. **收尾占 2.5 屏又重复。** 孤零零的大号「开发中」、三栏长句、一个大公式「Tool → Work」；「关注 Molis Tool 的进展」出现两次。
7. **丢了 Folio 版讲清楚的东西。** 由近到远的三层（光标旁 → 身旁 → 离开以后）、「它不是什么」、DropAgent 和牛来现在就能用。
8. **篇幅和定位相反。** 规格说 Tool 是「最空、最短的一页」，现在 10.7 屏。

### Folio 版：留什么，不要什么

- **留**：首屏「选中 → 动作 → 带来源的结果」的演示思路；三层接力讲出产品的结构；「它不是什么」；DropAgent、牛来的独立版入口。
- **不要**：整页色块（粉、藏青、黄、橙）与粗衬线；九段平铺；六个时刻六张卡；对照表；「合进来的工具」六宫格；插件舞台（对访客太深）；过时的快捷键（页面写 ⌥Space，仓库现在是 ⌥⌘Space）。

## 2. 方向

**最轻的一页。** 和社区的粗墨线、企业合作的软陶小物件拉开：Tool 几乎全白，字本身就是材料——放大的句子、纸、表格和真实大小的动作条。唯一的颜色是全站的选中色（杏橙淡底）——在 Tool 页上，「选中」就是它的颜色。唯一一张照片是首屏那道光。

**一个大胆决定：这一页本身就是 Tool。**

- 整页不画任何假的应用窗口、浏览器外壳或 Mac 窗口。演示都发生在纸上和页面自己的字上——「软件不必再是一个要去的地方」，页面也不画一个让人去的地方。
- 整页任意选中一段字，光标旁出现动作条；**选的东西不同，第一个动作不同**：带日期时间的先给「整理成日程」，英文先给「翻译」，一串数字先给「整理成表格」，其余是「清理格式 / 数一数 / 复制纯文本」。本机能做的在浏览器里真的做，要 AI 的标「示意」。这正是 4.2 那句「围绕这份内容和你选定的范围，找到接下来可以做的动作」。
- 你在这一页上做过的事，会出现在墙上下午 4:30 的「接续」里（只在当前标签页的内存里，不存储、不上传）。

**页面就是首屏照片里那面墙。** 墙上一次挂一件放大了的样品，像白展厅里的作品；往下滚是一个下午在过去。

**光标 = 一道光。** 「光标」里有个「光」。首屏白墙上的天光、选中时落下的杏橙淡底、做完退回菜单栏，是同一个意思：光落在哪里，软件就在哪里；做完，光移开。只在构图和图注里暗示，界面不画假光影。

## 3. 三段

### 首屏 · 窗前一张纸

- **左**：作品标签「Molis Tool · Mac 工具 · 开发中」；Molis Tool；「光标在哪里，软件就在哪里」；加粗一句；一行提示「选中右边纸上的任意一段试试。」+ 按钮「选中时间这一行」（键盘、触屏都能用）。没有 JS 时提示不出现。
- **右**：白墙天光的窗（4:5）；窗的左下角压着一张白纸，纸上是一则活动通知（示例）：标题、时间地点、一句英文、一行摊位价目——三种内容，选哪段出哪种动作。
- **动**：进页 2.2 秒没人动，由一枚示意光标演一遍：选中色铺过时间地点 → 动作条（整理成日程 · 清理格式 · 数一数）→ 窗上方出现日程草稿（加入前由你确认）→ 一起退下，提示换成「换你来：选中这一页上的任意一句话。」访客一按下、选中或按键就不再演。减少动态：停在草稿出现的那一帧。
- **标注**：纸角「示例」，草稿「界面示意 · 正在打磨的场景」。

### 一面白墙 · 一个下午

墙顶一行：编号、「一个下午，手边冒出的几件小事」、一根下午时间线（2:10 · 2:40 · 3:15 · 4:30，杏橙小太阳随滚动走）、「界面示意 · 示例数据」。五站，一次只看一站。每站左边是时间 + 加粗原句 + 一句原句；右边是一件放大了的样品——字本身就是材料，动作条按真实大小画，和整页选中时出现的那一条同一个样子：

1. **2:10「这些事情往往很小，却要经历打开应用、搬运材料、找功能、再把结果带回来的过程。」** 一排小字「老路：打开应用 → 搬运材料 → 找功能 → 带回来」逐个出现；下面一句格式乱掉的话用大字排着，多出来的空格用小点标出。老路被划掉，选中色铺过这句话，动作条（清理格式 · 数一数 · 复制纯文本，都标本机）出现，空格当场收拢、句末补上句号：「一步，结果留在原处」。
2. **2:40「眼前的小事，就在手边处理。」** 一份 6 页的 PDF 排成两行，第 2–4 页亮起一圈、微微抬起，「取出这几页 · 本机」，下面落出一叠副本，文件名旁「原件保留」；右边是首屏那张天光照片，被选中，「写一句说明 · AI」，照片下出现一句「白墙上，一道午后的天光。」
3. **3:15「结果还能成为下一步的材料。」** 一张取出的文字卡（甲乙丙三家报价）→「整理成表格 · 本机」→ 一张大表格逐行出现 →「比较三家 · 导出 CSV」；底下是原句「围绕海报准备日程草稿……也是正在打磨的使用场景。」
4. **4:30「收起以后，还能回来接着做。」** 右边只画菜单栏的右端（几枚淡圆点、Molis 图标、16:30）。墙上的三件东西（三家报价、秋日市集、那张照片）飞进图标；「接续」从图标下落下：三家报价对比、秋日市集 · 日程草稿、照片说明，每条一行来源。访客在这一页用过动作条的话，最上面多两条「刚才」。
5. **墙尾「工具出现多久，由你当下的需要决定。」** 大字；右边「它不是」四行（出自 Tool 设计纲领，待确认）。

- **宽屏（≥1000×640）+ JS + 不减少动态**：这一段钉住 320vh，往下滚墙往左走，每站占满一屏宽；只读原生滚动写进的 `--pin`，每站的 `--l` 从 0 到 1，样品里的东西按 `--t` 出现，可以倒回。第二站的 PDF 与照片按屏幕高度缩放，1280×720 也在一屏内。
- **手机、减少动态、没有 JS**：五站竖排，每站直接是完整的结果；手机上箭头转成向下，飞进菜单栏的那几件不画。

### 收尾 · 一屏

适合这样的时刻（大字原句）→ 当前进展：「开发中」+ 第 3 章阶段说明 +「已经有的 / 还没有的」块，原文收进「展开看原文」→ 右栏「和 Molis Work」（原句 + 签「计划中 · 范围与时间未定」+ 看看 Molis Work）与「现在怎么体验」（「Molis Tool 现在还不能下载。」+ 附录 A 里 DropAgent 和牛来那句原句 + 先在社区试试）→ 唯一的实心按钮「关注 Molis Tool 的进展」。

## 5. 整页动作条

- 选中的内容不同，第一个动作不同：日期时间 →「整理成日程」（AI，示意）；英文 →「翻译」（AI，示意；纸上那句给一句示例译文）；三个以上的数 →「整理成表格」（本机，真的按逗号切成表）；后面固定是「清理格式」「数一数」「复制纯文本」（本机，真的做）。
- 鼠标：出现在光标旁；触屏、键盘、按钮代选：出现在选区下面。Esc、点别处、滚走收起。
- 每次用过一个动作，记进内存（最多两条），墙上 4:30 的「接续」读它；刷新即无。

## 6. 事实与诚实

- 标题、加粗句、各站那句话、阶段、当前进展、DropAgent 和牛来那句都是 studio-intro 原句；样品里的材料、提示、示意结果是新写，代码里标了。
- 「它不是」四行与「三层」的结构出自 molis-tool 设计纲领，studio-intro 里没有，上线前请负责人确认。
- 不写快捷键、插件数量、版本号。纸上的活动、报价、照片说明都是示例数据。

## 7. 和第一版五屏方案的差别

- 第一版把「老路」「一个下午」「分寸」分成三屏三种画法（两条路、钉住的左文右图、一列大字），还有产品页共用模板的味道；现在合成一面横着走的墙，一个比喻贯穿：光标是光，页面是白墙，功能是展品。
- 「老路四步」不再独占一屏，成为墙上第一件东西；「它不是」成为墙尾的说明。
- 首屏去掉了单独的提示胶囊，纸本身就是邀请。
- 插件一段仍不上 Tool 页。
- 2026-10-16 负责人看了第一版的墙说「太丑了」：墙上是细线小方框、12px 小字，像没画完的线框，相邻两站还露出半截。第二版改成每站一件放大的样品、一次只看一站、动作条按真实大小画，负责人认可方向。

## 8. 需要拍板

1. 首屏是窗 + 压在窗角的一张纸（规格写「右边这件产品的窗」）。
2. 「它不是」四行上不上。
3. 文案「事实一致、措辞可压」的做法（来自逐页分镜那一轮，还没合进 main）。
4. 手机上墙是竖排（约 4 屏）；要不要再压短。

## 9. 第三版：照 Folio 版的骨架，七面彩墙（2026-10-22，已做，待验收）

负责人看过「一面白墙」后说不要按时间线走，改为参照 Folio 版的结构与内容，整页更紧凑，和整站一致，同时要有设计感。看方案时又定了三条：首屏沿用 Folio 版的光标演示；插件一屏不能删；要像 Folio 那样有足够的色彩，用动画配文字把产品讲清楚，注意细节，要高质感。

**总的做法。** 约七屏，一屏一个重点，宽屏下每段正好一屏（按顶栏高度留白，演示宽度跟屏幕高度收，1024×700 到 1920×1080 实测都放得下）。每段一面墙色：白、天蓝、玫瑰、奶油、深蓝，收尾回到纸色。一个动作一种颜色：翻译天蓝、解释鼠尾草绿、记下玫瑰、整理成日程杏橙、插件奶油黄，演示里的动作条和整页真的动作条用同一套颜色。不画编号，不画连线，不钉住，不横向滚动。循环演示在视口里才播，旁边有暂停键；小样品进入视口播一次，指过去重播。减少动态时直接停在结果上。所有演示标「界面示意」，示例数据另标。

| 屏 | 墙 | 内容 |
|---|---|---|
| ① 首屏 | 纸色 | Folio 版的光标演示：拖选一句英文，选区末端出现「翻译 / 解释 / 记下」，点翻译，带来源的译文卡片逐字出现。左边是产品页共用的首屏文字，下面「这一页上的任意一句话，都可以选中」 |
| ② 能力来到光标旁 | 白 | 同一句格式乱掉的话，两条道并排：以前要绕「打开应用、搬运材料、找功能、带回来」四站；用 Molis Tool 选中后点「清理格式」，一步，结果留在原处。两行说明是 studio-intro 原句 |
| ③ 由近到远的三层 | 天蓝 | 「离你越近，打扰越少。」同一场秋日市集接力三张样品：光标旁选中时间记下；身旁展开日程草稿卡；离开以后在菜单栏一角接续 |
| ④ 眼前的小事 | 玫瑰 | 4.2 原句做标题和导语，右边 3×2 小样品：清理格式、取出 PDF 里的几页、整理成表格再比较（本机），给图片写一句说明（AI，用 `tool-light`），海报变日程草稿、讨论整理成待办（正在打磨） |
| ⑤ 插件就是能力 | 奶油 | 「登记一次，处处可用。」以「生成字幕」为例：开关打开，光标旁、右键、拖放、命令条四处同时出现；字幕交给翻译接成一条链；关掉后入口一起收起，做好的字幕还在 |
| ⑥ 分寸 | 深蓝 | 「工具出现多久，由你当下的需要决定。」左边 `ex-skylight` 照片，右边「它会」四条和「它不是」四行（逐行划掉） |
| ⑦ 收尾 | 纸色 | 与第 3 节相同 |

- **代码**：`hero.tsx` 首屏演示；`scenes.tsx` 中间四屏；`parts.tsx` 演示里的小零件（选中色、逐字出现、图标、示意光标），不带 `'use client'`，服务端段落和客户端动作条都能用；`stage.tsx` 只留循环和播一次两种外壳。`wall.tsx` 删掉。
- **文案出处**：②的标题与四站，③的「由近到远的三层 / 离你越近，打扰越少」，⑤整屏，⑥的「它会」前半句与「它不是」，出自 Folio 版与 molis-tool 设计纲领，studio-intro 里没有，上线前需负责人确认。其余标了「原句」的是 studio-intro 原句。照片 `tool-light`、`ex-skylight` 也请一并确认。

## 10. 第四版：纸上的荧光笔（2026-10-22，已做，待验收）

负责人看过第三版说内容整体可以，视觉上还要再优化：颜色、布局、动效，并适当给访客一些亲手参与的感觉；不必完全照 Folio 版，可以自己重新设计。内容（文案、屏序、每屏演示）不变。

**总的做法。** 纸面安静，颜色只出现在「被选中、被动手」的地方，像在纸上用荧光笔划过：

- **一个动作一支笔。** 色板换成更亮的六支笔（杏橙、天蓝、鼠尾草绿、奶油黄、玫瑰、丁香），图标是浅底上的同色深字，不再是彩底白字。
- **标题被划一下。** 每屏标题浮上来以后，荧光笔从左往右划过最要紧的几个字（光标旁 / 打扰越少 / 就在手边处理 / 处处可用 / 你当下的需要）；深蓝墙上改成字脚下一道黄线、字变柠檬黄。划的字记在 `content/site/tool.ts` 各段的 `mark`。
- **一屏一张纸。** 每段是一张上沿圆角的纸，压在上一段上面；墙色依次是纸色、白、天蓝、纸色、丁香、深蓝、纸色。天蓝和丁香墙上的辅助字换成同色相的深色，过 4.5:1。
- **开窗。** 以前与现在两条道、画廊的墙进入视口时从中间往两边打开；带投影的纸不用（clip-path 会剪掉影子）。

| 屏 | 墙 | 改了什么 |
|---|---|---|
| ① 首屏 | 纸色 | 不变，只换成新色板 |
| ② 能力来到光标旁 | 白 | 「用 Molis Tool」那条道是奶油黄。演示里的「清理格式」是真按钮：一按循环停下，乱的那句收拢成干净的一句、出现「一步，结果留在原处」，同时记进整页动作条「离开以后」的接续；再按退回乱的样子，暂停键变成「继续播放」 |
| ③ 由近到远的三层 | 天蓝 | 三张纸照旧接力，「我的」那一条用玫瑰底，跟着整行一起进场 |

## 11. 第五版：展厅的墙 + 鼠标编排（2026-10-23，已做，待验收）

负责人看过第四版说颜色不好看，并指出演示里鼠标是重点，要带着观众的注意力；画廊「清理格式」那一件要看好几遍才明白。拆开看，看不懂的原因是：光标和结果同时在动、选中没有过程（直接亮）、动作条和光标不在一处、做完了没有交代。内容与屏序不变。

**墙。** 换成「展厅的墙」：每屏一面低饱和的浅墙，东西挂在墙上；整页唯一亮的颜色是选中色（暖橙，`--sel`），动作的颜色压低成颜料色，只落在小图标和新出现的入口上；做完的那句用一种暗绿（`--done`）。

| 屏 | 墙 |
|---|---|
| ① 首屏 | 纸色 |
| ② 能力来到光标旁 | 亚麻 `#f5f0e6` |
| ③ 由近到远的三层 | 月白 `#eef1f4` |
| ④ 眼前的小事 | 雾 `#eef0eb`（画廊的墙板再深半档） |
| ⑤ 插件就是能力 | 沙 `#ece5d8` |
| ⑥ 分寸 | 石板 `#2a3140`，字反白，标题强调是字脚下一道赭黄 |
| ⑦ 收尾 | 纸色 |

每屏标题最要紧的几个字像被选中一样铺上选中色（石板那屏是赭黄下划线），仍记在 `content/site/tool.ts` 各段的 `mark`。

**鼠标编排。** 每段演示都按同一套规矩，光标是带着人看的那样东西：

1. 一次只动一样：光标在动时别的都停着；结果出现时，光标停住或让开。
2. 一遍分三拍：之前停一会儿 → 动手 → 之后停久一点，留下一句「做完了」（`content/site/tool.ts` 里的 `done`，示意）。
3. 动手的顺序固定：光标从画框外进来 → 变成 I 形拖选，选中色跟着拖过的地方一截一截铺开（框选时拖出一个实线描边、铺淡选中色的选框）→ 松手，动作条出现在选区末端 → 光标走到第一个动作上，停一下，按下 → 光标让开 → 结果就在原处发生（收拢、出卡、排序都从原来的位置变过去）。
4. 光标走弧线，先快后慢；按下有一下轻微的缩放。

| 演示 | 编排 |
|---|---|
| 首屏 | 先停在译文上；再演一遍：拖选两行英文 → 翻译 → 译文一个字一个字贴在旁边，带出处 |
| 以前与现在 | 左边光标跑四个应用（底下的点一个个亮）再回到纸上才收拾好；右边拖选乱的一句 → 清理格式 → 就在原处收拢，「一步，结果留在原处」 |
| 三层 | 光标旁：选中日期 → 记下；身旁：框住海报 → 旁边出日程草稿；离开以后：菜单栏图标 → 接续面板 → 回到你离开的地方 |
| 插件 | 按开关 → 四处入口依次亮起 → 一条链走下来 → 再按一下，入口收起、链上那一步变灰，字幕还在 |
| 画廊六件 | 清理格式、取出 PDF 里的几页、整理成表格再按单价排序、给图片写一句说明、框住海报变日程草稿、讨论整理成待办，各自一段编排，做完留一句 |

- **代码**：`cue.ts` 是编排引擎（光标、拖选、按下、让开、收拢；时钟离开视口、切到后台、按暂停时停下，回来接着走），`scripts.ts` 是每段的剧本，`tool.css` 写每一拍的样子。舞台上 `data-run` 表示编排接管，`data-cue` 记着演到的几拍；没有 `data-run` 时就是做完的样子，所以没有 JS、减少动态时都停在结果上。两样能亲手按的（清理格式、插件开关）照旧，按了以后编排让位给访客。
- **实测**：1440×900 各段逐帧录过；390 宽手机画廊在名字下面照常演，减少动态时各屏停在结果上，无横向滚动。
