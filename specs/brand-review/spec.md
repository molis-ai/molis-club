# 品牌方向评审：预览台与投票

## 背景与目标
日光、Folio、夜曲、深空与 Edition C 五个品牌方向各有首页和 Molis Work 产品页，原本散落在十个链接里。需要一个页面把它们并排看完，再用投票页收集“更喜欢哪一个、为什么”，让团队一起提建议。
完成等级：功能可用，桌面与手机布局验证后随现有部署发布。

## 范围
- `/demos/brand/compare` 预览台：左侧五个方向（首屏缩略图、名称、三项特征），右侧加载所选的真实页面；可切换首页 / Molis Work 与桌面（1440×900 等比缩放）/ 手机（390×844）。选择写入 `?d=&p=&v=`，链接可直接分享。下方“一览”并排十个页面的桌面与手机首屏截图，点击即在预览台打开；每个方向都可新窗口打开或直接去投票。
- `/demos/brand/vote` 投票页：选一个方向（必填）、为什么（5–1200 字）、别的方向里值得留下的（可选，≤1200 字）、称呼（≤40 字）。无需登录，同一浏览器以 localStorage 中的随机 id 识别，可改票。投票前结果默认收起，可主动展开；结果含票数、占比和可按方向筛选的理由。
- 不改动五个方向页面、品牌、认证与其他栏目。页面标注为探索稿，不代表最终设计。

## 数据
- 新表 `design_votes`，迁移为 `drizzle/0002_curved_ultron.sql`。`id` 是投票人随机 UUID，`choice` 只接受五个方向的 slug，同一 id 再次提交覆盖原票。
- `GET /api/design-votes` 返回票数、最近 200 条理由；带 `?voter=` 时附上本人的票。列表不返回 id。`POST` 做同源校验和长度校验，参数化写入。
- 称呼、选择和理由对所有访问者可见，页面已说明。匿名投票没有防刷能力，只适合内部评审；公开前需要改为登录投票或加限流。

## 上线
Sites 部署会自动应用 `drizzle/`。Cloudflare 自有账号部署需要对该 Worker 绑定的 D1 执行一次：

```sh
npx wrangler d1 execute <D1 名称> --remote --file drizzle/0002_curved_ultron.sql
```

执行前投票接口返回 503，投票页显示“结果暂时没能加载”，提交时提示“这一票没能保存”，预览台不受影响。

## 验收
1. `npm run check`、`npm run lint`、`npm test`、`npm run build` 通过；本地服务运行时 `node tests/brand-review-http.mjs` 通过（只读，不写票）。
2. 1440×900 与 390×844 下两页无横向溢出、无控制台错误；预览台切换方向、页面与设备后加载对应真实页面，手机框与舞台圆角无 iframe 溢出。
3. 投票新建返回 201，同一设备改票返回 200 且只保留一票；未知方向、空理由、缺称呼、外站请求均被拒且不写库。
4. 键盘可切换方向（方向键、Home/End），单选、输入和筛选有可见焦点；减少动态偏好下没有过渡。
