**A9 联系表单：同一邮箱可以多次提交，成功后回到来处**

- 提交契约：表单第一次发送时生成提交 id（`crypto.randomUUID()`，不支持时不带），失败重试沿用；服务端以 id 为主键，`ON CONFLICT(id) DO NOTHING`。不带 id 的旧请求由服务端生成；带了但不是 UUID 返回 400。同一邮箱的不同留言各存一行。返回值仍是 `status`、`message` 两个键，消息改为「你的留言已收下。」。
- 迁移 `drizzle/0003_applications_multiple_submissions.sql`（`npm run db:generate` 生成）：`email` 的唯一性原本是独立的唯一索引，只需 `DROP INDEX`，不用重建表；新增 `topic`（可空）和 `allow_display`（默认 0，给 A7 用）。先在 `.wrangler/state` 的副本上演练（两条旧数据保留、同一邮箱可再存、完整性 ok），再对本地库执行（迁移前写入的一条「A9 本地迁移验证」保留）。线上库未动。
- **部署顺序**：新接口会写入 `topic`、`allow_display`，线上库必须先执行 0003 再部署，否则提交返回 503。执行线上迁移要负责人另行确认。
- 共享表单 `use-contact-form.ts`（五个方向共用）：随提交发送 `id`、地址栏的 `topic` 和 `allowDisplay`（表单里有这个勾选时）。返回值只增不减，多了 `topic`。预填改为渲染时直接读地址栏（`useSyncExternalStore`），方向和内容是派生值，访客改过的优先；站内跳转进来的第一帧就是预填好的，阶段 1 记下的「先闪一下企业合作」随之修好。服务端渲染时仍是默认方向，直接打开时在水合后改正，与原来相同。

## 讨论要点

- 现在的「把工作做轻，把时间还给生活。」太像喊口号。高端的愿景不靠口号，靠内容和网页设计；好用的产品也不靠介绍，靠产品自己。

- 恢复一骏原来的 A/I 词组变体：这是团队介绍页，不是产品介绍页。
- 往下滑依次是产品陈列、团队介绍、我们的文章，然后是登录和社区。
- 这个站给老板看，也供我们演讲时使用。
- 几个域名各有主题和表现重点：统一风格，不统一内容和样式。
