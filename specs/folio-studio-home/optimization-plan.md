## 一、已定事项

### A1 首页：四个产品保持独立，加上 World 入口（简报）

**对象**：首页产品区 `#products`。源码 `app/demos/brand/folio/page.tsx`（`CoreProduct` 渲染 Work，`Lines` 把 Tool、Life、Story 渲染成整屏色纸 `.fo-sheet`）；样式 `folio.css`、`home.css`；数据 `content/folio.ts` 的 `folioStudio.lines`（领域签、阶段）与 `folioHomeCopy.products`（首页简介）。

**已定**（10/11 会议 D2、D11，10/12 负责人确认）：Work、Tool、Life、Story 不合并展示，首页各占一屏、各自跳到自己的页面；首页已认可的产品动效和介绍保留，不推倒重做。画面以后可以成对设计（Work 与 Tool 是白天、人在桌边；Life 与 Story 是夜晚、人在沙发或床上），那是视觉那一路的事，不在本项。

**要解决的问题**：Molis World 是 10/11 定下的新方向（Life + Story = World），首页上还没有它；但它只是概念，不该和已经在做的四个产品同等分量。

**想要的感觉**：读完 Story，自然知道 Life 和 Story 还能连成一个属于自己的世界，好奇的人可以点进去；不打断四个产品的节奏，也不会让人以为 World 已经能用。

**必须包含的事实**

- World 的一句话（已定）：「现实和故事，都住进你慢慢长大的世界」。
- 状态「概念设计」，链到 A2 的 World 页。
- 过渡句（暂用，P2 定稿）：「生活里有陪伴，故事里有远方，你的世界是归处。」

**不能做**：不给 World 单独一整屏；不改 Work、Tool、Life、Story 四屏现有的画面、动效和简介（A12 d 的领域签修正除外）；不写下载、试用。

**依赖**：A2 的 World 页；首页基线为 d880338（10/12 已定，试改版不采用）。

**验收**：首页仍是 Work、Tool、Life、Story 四屏，画面、动效、简介与 d880338 一致（领域签修正除外）；Story 之后能看到 World 的入口，标「概念设计」，链接可达；减少动态时没有残留的叠压位移。

### A2 新增 World 页（概念，简报）

**对象**：新路由 `/demos/brand/folio/world`。新建 `app/demos/brand/folio/world/page.tsx` 与 `layout.tsx`（metadata）；文案放 Folio 专用导出（如新文件 `content/folio-world.ts`）。

**现状问题**：Molis World 是 10/11 确定的新产品方向（Life + Story = World），站内没有页面；首页（Story 之后的入口）和 Life、Story 页都要链到它。

**已定的前提**

- World 暂时没有原型和仓库，是概念。状态写「概念设计」，不放下载或试用入口，主行动是「关注进展」。
- 「Life + Story = World」现在就对外讲；涉及 World 的地方一律标「概念设计」，不写成已经打通。
- 视觉风格还在探索：先用 Folio 现有组件和样式实现，World 的颜色暂用鼠尾草绿占位，不新增插画和依赖。风格定了以后整体替换组件，文字不动。
- 参照：产品页参照 Cursor，页面简单，一眼知道是什么，有往下看的引导（会议 D8）；站内 Tool 页「一个例子贯穿」的讲法可以借鉴。示例都标「概念示意」。
- 讨论稿要点见附录 C。

**想要的感觉**：一眼明白 World 是一个属于你、会慢慢长大的小世界，现实里常去的地方和故事里的经历都能住进来；读完觉得温暖、想关注它，也清楚它还只是概念。

**要讲清的事**（顺序和版式由执行者定）

- World 是什么：连接真实生活和虚构故事、持续生长的个人空间。不连别的产品也能用：手工加入地点、按自己的方式布置、随时回来接着改。
- 一段例子旅程：常去的面馆放进世界 → 以它为灵感走进一个故事 → 带上你的 Agent 或一支队伍 → 一起完成 → 纪念物和回忆带回来 → 有了真实的想法，可以交给 Life。每一步属于哪个产品要看得出。
- 三个产品的关系：Life 是真实生活，Story 是虚构世界，World 是你的小世界；三个各自独立，连接它们的是你选择共享的数据和同一个身份。
- 分寸：附录 C 的六条规则（现实归现实；分享不等于公开；Agent 在做什么看得见；托付有边界；离开、暂停、结束是三件事；作品分版本）。
- 现在在哪一步：World 概念设计，还没有可用版本；Life 原型探索，还不能下载；Story 开发中，四个世界在开发版里能走完，还不能下载。

**已定文案**：首屏标题「现实里的地方，故事里的经历，都住进你慢慢长大的世界。」；一句话「现实和故事，都住进你慢慢长大的世界」；状态「概念设计」；主行动「关注进展」（`contact?topic=world`）。

**不能做**：不放下载、试用、注册入口；不写成已经打通；不新增插画和依赖（视觉风格待定，见 P13）；示例都标「概念示意」或「示例旅程」。

**站内配套**

- 顶栏「产品」下拉平铺五个产品，顺序 Work、Tool、Life、Story、World，不分组（会议 D11）；World 的简介用「现实和故事，都住进你慢慢长大的世界」，标「概念设计」。
- 「接着看」顺序：Work → Tool → Life → Story → World → Work。实现时把 `shared.tsx` 里的产品顺序、链接、色调、简介改为读 Folio 自己的产品列表（含 world），`kit.tsx` 的 `NextProduct` 跟着改；不改共享的 `LineId`、`lineNames`。
- 页尾「产品」一栏加 Molis World。
- 联系页预选：新增 `topic=world`，方向「早期体验者」，内容「想关注 Molis World 的进展。」。预选表在共享的 `content/studio.ts` 的 `contact.topics`，新增键是纯增量、不影响其他方向；如要严格不碰共享文件，就在 Folio 侧扩展预选表。
- 页面描述（meta description）：Molis World 是一个持续生长的个人空间：把喜欢的地点、伙伴、经历和作品放在一起，连接真实生活与虚构故事。目前是概念设计。
- `scripts/export-folio-preview.mjs` 加上新路由；`tests/folio-browser.mjs` 加一项 World 页检查。

**验收**

- 「要讲清的事」五项都讲到；状态签和示意标注都在；没有下载、试用、注册等入口。
- 「关注进展」进入联系页时，方向和内容已预选。
- 下拉、页尾、「接着看」三处都能到达 World，World 之后回到 Work。
- 手机上例子旅程按顺序读得下来，不拥挤。

### A3 Life 页按新方向重做（简报）

**对象**：`/demos/brand/folio/life`，源码 `app/demos/brand/folio/life/page.tsx`、`life.css`。现在的文案来自共享的 `content/molis-life.ts`（不改），新文案放 Folio 专用导出（如 `content/folio-life.ts`）。

**现状问题**

- 页面讲的是「把琐事交代出去」，重心是事务处理。新方向里 Life 是真实生活世界：一个懂你、陪你的个人 Agent，提供理解与陪伴、情绪价值，也处理现实里的信息、计划和行动。Life 仓库 10/7 的 `PRODUCT.md` 已经写成「提醒、建议与陪伴」，页面落后于它。
- 「八个场景」「手机和电脑」「会合进来的」三段都是路线图，且多标「规划中」，占的篇幅多。
- 「它替你接住的三件事」最具体、最打动人，却只是三张普通卡片。
- 页面没提和 Story、World 的关系（已定对外讲）；「和 Molis Work 同一套插件思路」与新方向关系弱。

**想要的感觉**：首屏一眼看出 Life 是「一个懂你、陪你的 Agent」，读完觉得被理解、被照顾，而不是又一个待办工具。参照 Cursor 的产品页：页面简单，一眼知道是什么，有往下看的引导（会议 D8）。

**要讲清的事**（顺序和版式由执行者定）

- 它是谁：一个懂你、陪你的个人 Agent，提醒、建议与陪伴；也帮你处理现实里的信息、计划和行动，琐事是其中一部分。
- 一个具体例子从头走到尾：现有的三件事（退衣服跟进、陪妈妈看海、接住好奇心）是最好的素材，每一步标「示意」。
- 它怎么理解你：保留你的原话和来源，可以修正，一次点击不会被当成你的性格；它记得什么、怎么改、怎么忘。
- 决定权在你：可以随时暂停它；托付它跟进一件事之前，先说好范围。
- 和 Story、World 的关系：Life 是真实生活；在 World 里冒出的真实想法，可以交给 Life 准备计划。World 标「概念设计」，链到 World 页。

**可以压缩的**：「怎么交代给它」「生活的八个场景」「手机和电脑」「会合进来的」都是路线图，最多各留一行；八个场景注明「这是方向，不是首发清单」。「和 Molis Work 同一套插件思路」去掉；Seentoo（散步与看见）可以留。

**不变**：状态签「原型探索 · 还不能下载 · 页面里的例子都是示意」。

**事实核对（必须做）**：写「理解与陪伴」前，对照 Life 仓库 `docs/产品设计.md` 与 `specs/life-foundation/spec.md`。目前的原型里，偏好由用户填写，规则只按有限字段匹配；自然语言理解、跨内容联想和长期关系都还没有。页面上凡是超出这些的，一律标「规划中」或写成方向。

**验收**：首屏一眼看出 Life 是「懂你、陪你的 Agent」；路线图类段落各只剩一行；超出原型的能力都有「规划中」或「示意」标注；页内能到达 Story 与 World。

### A4 Story 页调整（简报）

**对象**：`/demos/brand/folio/story`，源码 `app/demos/brand/folio/story/page.tsx`、`story.css`。现在的文案来自共享的 `content/molis-story.ts`（不改），新文案放 Folio 专用导出（如 `content/folio-story.ts`）。

**现状问题**

- 页面只讲「一个人走进一个世界、带一样东西回来」。新方向加了三件事：人和 Agent 都能玩、可以带自己的 Agent 队伍进来、可以自己创作世界。
- 「和游戏、和聊天有什么不同」第一条写「不是游戏：没有分数、胜负和打卡」，和新方向的「游玩」冲突。
- 「归来」没有去处；现在它可以接到 World。

**已定**

- 袖珍博物馆暂时留在 Story，四个世界不变。
- Story 不限定是不是游戏：世界可以是游戏，也可以不是。

**想要的感觉**：想进去玩一趟；知道可以一个人去，也可以带上自己的 Agent；回来时手里有东西，并且知道带回来的可以放进自己的世界。参照 Cursor 的产品页：简单、一眼知道是什么、有往下看的引导（会议 D8）。

**要讲清的事**（顺序和版式由执行者定）

- 核心体验不变：此处 → 彼处 → 归来。首屏标题「走进另一个世界，经历另一种生活，然后回来。」保留，导语加上「一个人去，或带上你的 Agent」。

### A9 联系表单：同一邮箱可以多次提交，成功后回到来处

**对象**

- 数据表：`db/schema.ts` 的 `applications`（`email` 带 `unique()`）。
- 接口：`lib/community-api.mjs` 的 `saveApplication`（`INSERT … ON CONFLICT(email) DO NOTHING`），路由 `app/api/join/route.ts`。

- 文案：共享的 `content/studio.ts` 里 `contact.success`、`contact.successActions`、`contact.topics`。
- 测试：`tests/community.test.mjs`（现在断言同邮箱第二次提交只留一行）、`tests/folio-journey.mjs`。

**现状问题**（`specs/folio-studio-home/spec.md` 待办已确认）

- 同一邮箱第二次提交会被丢弃。例如关注过 Work 的人，之后想谈企业合作，提交不进去；A7 的分享入口也会受影响。
- 成功页固定给「回到 Molis AI」「看看 Molis Work」，不管访客从哪里来。
- 成功文案把实现细节写给访客：「同一个邮箱重复提交时，保留先前那一份。」

**方案**

1. 提交契约：不同的留言各存一行；同一次提交的重试只存一次。做法：表单每次打开时生成一个提交 id（`crypto.randomUUID()`）随请求发送；服务端用它做主键，改为 `ON CONFLICT(id) DO NOTHING`。旧客户端不带 id 时，服务端自己生成（向后兼容）。服务端校验 id 是 UUID 格式。
2. 迁移：用 drizzle 生成一次迁移，去掉 `applications.email` 的唯一约束；顺带加两列：`topic`（可空，记录从哪里来，如 enterprise、work、share-artist）、`allow_display`（是否同意展示，默认否，给 A7 用）。SQLite 改约束需要重建表，迁移必须保留已有数据；先在 `.wrangler/state` 的副本上演练，再对本地数据执行，不删任何行。不动线上数据库，发布前另行确认。
3. `use-contact-form.ts`：生成并发送提交 id；把地址栏的 `topic` 一起发送；保持对五个方向的向后兼容（接口和返回值不变）。
4. 成功后回到来处（Folio 联系页）：按 `topic` 决定按钮。`enterprise` →「回到企业合作」；`work`、`tool`、`life`、`story`、`world` →「回到 Molis …」对应产品页；`feedback`、`creator` 和分享类 →「回到社区」；没有 topic →「回到首页」。按钮文案放 Folio 专用导出。
5. 成功文案：删去「同一个邮箱重复提交时，保留先前那一份」。因为接口行为对所有方向都变了，这一句在共享的 `content/studio.ts` 里也要改（这是事实修正，不属于品牌改动）。保留「目前不会自动发邮件」。
6. 更新 `tests/community.test.mjs`：同邮箱两条不同留言存两行；同一提交 id 重试只存一行；不带 id 的旧请求仍然成功。更新 `tests/folio-journey.mjs` 里的成功去向检查。

**不在本项内**：「关注进展」的按钮文案、提交前的「接下来会发生什么」说明、企业访客分流，见 P14。

**对象**：`/demos/brand/folio/solutions`，源码 `app/demos/brand/folio/solutions/page.tsx`、`solutions.css`；文案 `content/folio-cooperation.ts`（Folio 专用）。现在的顺序：首屏（含示意卡）→「我们能一起做的事」四段服务 →「从你手边的一件事开始」（三条任务类型 + 原则框 + Work 入口）→「合作如何开始」三步 → 结尾。

**现状问题**

- 合作过程讲了三遍：首屏示意卡（要什么 → 业务经验 + Agent 执行 → 团队跑通验收）、四段服务（每段三小段文字）、「合作如何开始」三步，合计占页面大半。
- 两套流程并存（四段服务、三步开始），读者分不清四段是可单选的服务，还是一次合作的四个阶段。
- 企业读者是带着「我的问题能不能做」来读的，而具体问题只有三条泛化的任务类型，字号和篇幅都小。
- 最有辨识度的立场「执行交给 Agent，关键判断留给人」只是一个侧栏框。
- 没有证据（由 A8 补）。
- 文案偏咨询报告：「贴近业务现场的共建方式（FDE）」用了术语，服务描述长句多。

**推荐方案：五段**

1. **首屏**：标题保留「把 AI 用进业务，把能力留在团队。」。导语只留承诺，不再复述过程；可以用一个具体场景来讲，示例：「比如一份每周都要反复核对的调研：整理资料、核对来源交给 Agent，你们的人只做比较和判断。」右侧示意卡改放立场「执行交给 Agent，关键判断留给人」及其说明（付款、发布、报价、权限与重要业务决定由你们确认），侧栏框删去。
2. **可以从哪些问题开始**（场景卡片，页面主体）：沿用现有三条（一份需要反复核对的调研、每周都在重复的整理工作、只有少数人掌握的业务流程），每张卡写清：在解决什么问题、我们能帮忙做什么、预期改善是什么。标题和关键结果要大，补充说明小。不写虚构的效果数字。
3. **一次合作怎么走**（把四段服务和三步开始合成一条三步的线）：带一个问题来 → 一起跑一小段 → 按结果决定下一步。每步写三件事：你们提供什么、我们一起做什么、留下什么。四段服务的内容（发现、共建、验证、交接）分进这三步，第三步的「留下什么」就是「能力留在团队」的落点。
4. **做这件事的人**：A8 的证据段，末尾是「认识团队」。
5. **结尾**：「带什么来」的提示只留在这里（带上现在的做法、遇到的困难，或一份还不够满意的结果），按钮「聊聊企业合作」。

去重规则：合作过程只在第 3 段完整讲；「能力留在团队」只在标题和第 3 段第三步；「关键判断留给人」只在首屏立场卡；「带什么来」只在结尾。「FDE」改写为「和实际使用的人一起共建」。

**需要拍板**

- 是否采用五段结构（handoff 曾定顺序为「合作如何开始 → 各个场景 → 联系」，10/10 重写时又改成了现在的顺序）。
- 证据段写不写成员姓名；导语要不要直接说「还没有可以公开的案例」。
- 成员资料什么时候同步（负责人已说会同步）。
- 导航名是否从「解决方案」改为「企业合作」（见 P8）。

**可先做**：A8；A12 e。

### P8 全站命名与文案规范

**对象**：全站文案；顶栏与页尾栏目名（`shared.tsx` 读共享的 `navLabels`、`footer` 和 `folioStudio.nav`）；各页按钮。

**现状问题**

- 同一产品有三套一句话（首页、下拉与「接着看」、详情页首屏），下拉里的 Life 还是旧定位（已由 A12 a 修正）。

- 返回首页有四种写法（回到 Molis AI、回到首页、回首页、回工作室）；文章在社区叫「观点」。

2. **标签**：领域签只写领域（Work「工作 · 工作台」、Tool「工作 · 光标旁」、Life「生活」、Story「故事」、World「个人世界」），阶段签只写阶段；是否能下载统一写「可以下载」或「还不能下载」。
3. **栏目和按钮**：栏目名用名词，按钮用动作。

| --- | --- | --- |

5. **排版**：中英文、中文与数字之间加空格；引号用「」；一句话简介不加句号，标题和正文句子加句号；英文短句（Products、Made of curiosity.）只做排版点缀，不承担说明。

### 附录 C Molis World 讨论稿要点（10/11，负责人提供，概念阶段）

- **愿景**：用户和自己的 Agent 一起生活、经历和创造。现实里的地方（外卖、商场、景区等）会成为个人小世界的一部分；也可以带着一支 Agent 队伍进入虚构世界。
- **三者关系**：Life + Story = World。三个都是独立产品，由用户自己选择的数据和同一个身份连起来。World 必须有自己的价值：搭建、布置、不断变化。
  - **Life**：现实生活的世界。个人 Agent，理解与陪伴，情绪价值；真实的信息、计划与行动。
  - **Story**：虚构的世界。人和 Agent 都能玩；带上自己的 Agent 队伍一起协作、探索、创造。
  - **World**：连接现实与虚构、持续生长的个人空间；可以单独开始：手动加地点、布置、重游。
- **例子旅程**：一家面馆进入你的世界 → 启发一个故事 → 选一个 Agent 或一支队伍 → 一起完成 → 把纪念品和记忆带回来 → 可以把一个真实的想法交给 Life。
- **共用概念**：世界、地点、人物与 Agent、队伍、旅程、经历、作品。
- **规则（写文案时不能违背）**
  - 现实数据和虚构数据分开；剧情不会改写真实的订单、营业时间或记录。
  - 分享不等于暴露订单、地址或行踪。
  - Agent 的提议、执行中、等待确认、暂停、结果要清楚可见。
  - 离开页面、暂停 Agent、结束旅程是三件不同的事。
  - 委托要有范围、时间和动作的限制。
  - 创作有草稿、试玩、已发布三个状态；编辑不会打断别人正在玩的内容。
