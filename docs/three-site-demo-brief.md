# Molis AI：三个独立网站的设计与内容

更新：2026-09-22。当前为本地设计 Demo，分享、打包与发布均暂缓。

## 用户已经明确的方向

三个网站分别设计，不再作为共享栏目导航的三份首页提案。上一版把网站切换、全局栏目和本页导览叠在一起，造成信息拥挤，也模糊了内容主线；该结构已撤下。`/demos` 现在只转到品牌网站，三个网站各有独立入口、导航、页脚和页面标题，不在页面里放置比较器。

统一品牌 slogan：**始终好奇，持续创造**。品牌与社区对外均为 Molis AI，主产品名 Molis Work。技术上继续复用当前应用，不因此新建项目、数据库或更改现有官网。

## 品牌网站

入口：`http://localhost:3100/demos/brand`

任务：让访客认识团队、理解团队为什么做这些产品，并判断是否值得交流。

内容顺序：

1. 首屏只说 slogan 和团队定位：探索人与 AI 如何共同创造的产品工作室。
2. 代表作品：先给 Molis Work 足够的展示空间，再展示 niul.ai 与 Elsewhere。每件作品说清用途、阶段与真实入口。
3. 创造方式：把问题问具体；带到真实生活里；把方法分享给后来的人。
4. 场景合作：先理解问题与现有做法，再讨论小范围验证及产品上手。CGS、Evrik、Aether 收在具体问题的展开说明中，明确是探索。
5. 愿景：做一家无限游戏的公司；彼此信任、自主探索、共享经验与成果。
6. 从一次具体交流开始。

视觉：以大尺度中文字、单幅图像和疏朗的作品集布局建立主次。海军蓝保留品牌识别，雾蓝、灰绿用于作品画面；交互只回应用户操作。移除旧版多层导航、浮动切换条、多余眉题和插画旁的第二套口号。

## 产品网站

入口：`http://localhost:3100/demos/product`

任务：让访客理解 Molis Work 如何帮助一项工作持续推进，以及现在怎样开始使用。

内容顺序：具体价值 → 一个完整可操作的访谈指南任务 → 个人使用场景 → 其他产品 → 开始使用与常见问题。

工作台是唯一的主要视觉：可以查看材料、切换三阶段、确认结果或要求继续调整。它是演示，不连接真实模型或个人数据。以浅色工作文档、雾蓝留白与深色工作台框架组织视觉，产品目录采用紧凑列表。Molis Work 始终位于产品目录首位，Elsewhere 在本页展开说明，不跳转到另一个 Demo。

Work OS 是长期方向；当前以本地使用为主，团队云协作、个人助理不得写成已经上线。所有开始使用入口指向真实仓库说明，不造下载文件。

## 社区网站

入口：`http://localhost:3100/demos/community`

任务：让新人先动手尝试，再发现作品、带走方法、认识同路人。

内容顺序：一个可调参数并下载 SVG 的线条实验 → niul.ai、Artist Skill、DropAgent 三件作品 → 三个可展开复制的方法 → 创作者与两篇观点原文 → 实际参与入口。

视觉：清楚的邀请、大块留白和一个可玩的图形。作品逐件介绍，知识按需展开，移除贴纸拼贴、密集分类按钮与多层卡片。没有虚构社区人数、活动或用户贡献。

## 品牌网站的三个视觉方向（2026-09-23）

用户从 8 组设计图中选了 Daylight、Jun Ioneda、Cosmos（2023 深色版与现版）、Teenage Engineering，不喜欢 Spline 式装饰 3D。据此做了三个品牌首页方向，每个包含首屏和后续几屏真实内容，供比较与筛选；原 `/demos/brand` 保留不动。

- 日光 `/demos/brand/daylight`：参考 Daylight。暖奶油底、思源宋体细字标题、带晃动树影的圆角摄影首屏、滚动时逐字浮现的立场句、树影落在 Molis Work 工作记录纸面上的作品区、「无限游戏」短信。
- 玩心 `/demos/brand/playful`：参考 Jun Ioneda 与 Teenage Engineering。钴蓝底配杏橙、奶油与海军蓝描边的站酷庆科黄油体大字，可点击的 niul.ai 小牛；白底作品目录用型号、版本与几何图标。
- 宇宙 `/demos/brand/cosmos`：参考 Cosmos。作品缩略图在三维空间中飘向访客，可切换亮/暗；之后每屏一块色块只演示一件作品（Molis Work 换会话、niul.ai 状态、Artist Skill 风格切换）。

三站共用的事实边界不变：阶段标签沿用本文与仓库调研；工作记录和状态演示标明示意；艺术试样标明非艺术家原作。用户尚未选定方向。

## 内容边界

- 原有社区、百科、产品、解决方案、观点五类内容与原文保留在原站。本轮调整的是三个独立网站的首页叙事，不将五类内容强行混排在每一站。
- 原站完整目录、成员介绍、作品详情与文章原文在新标签打开，三个新网站自身导航停留在本页。
- 品牌页 CGS / Evrik / Aether 分别是部分能力验证、内部技术验证和方案设计。它们不是已交付客户案例。
- Elsewhere 为内部体验，尚未开放下载。公开仓库、可下载安装、已上线和用户认可属于不同事实。
- Q4 沟通数、Case、应用上架、Star、插件、用户与粉丝数字是目标，不作为官网成绩单。
- 雕塑与作品氛围图是原创概念素材，Work 画面明确为工作记录示意；没有把生成图像冒充团队实拍或真实客户成果。
- 不新增账号、收集报名或发送消息；联系入口沿用现有官网真实页面。

## 设计依据与实际参考

本轮亲自浏览、观察真实页面后提取设计方法：

- 品牌：[ustwo](https://ustwo.com/)、[IDEO](https://www.ideo.com/)。借鉴单一强标题与大幅作品的取舍，内容先讲清团队和作品，再建立信任。
- 产品：[Linear](https://linear.app/)、[Craft](https://www.craft.do/zh-CN)。借鉴产品画面的尺度、连续任务叙事、低文字密度与具体使用场景。
- 社区：[Ink & Switch](https://www.inkandswitch.com/)、[Playdate](https://play.date/)。借鉴先让访客动手，以及一次把一件作品讲清楚。

这不是对其页面的复制，也不是用户已经认可本轮视觉的证明。

业务依据继续沿用[官网讨论会议](https://kcn8ld2n1dh4.feishu.cn/minutes/obcn6m9dl5h41nx7aj5n3yfs) 17:20–33:06、Q4 最新规划、仓库 `content/` 与[逐仓库研究](./demo-repository-research.md)。参考合集仍在[飞书网站设计参考库](https://kcn8ld2n1dh4.feishu.cn/docx/DEg7dffEGol3M4xSv2icA98VnRh)。

## 本地状态

三个网站在隔离工作树中修改，原工作树保持不动。本地启动命令：`npm run dev -- --host 127.0.0.1 --port 3100`。

各站需要分别检查桌面与手机、主导航、展开/复制/下载或任务阶段交互、减少动态偏好、完整内容入口。工程检查、Agent 实操与用户的审美验收分别记录，不互相替代。

### 2026-09-22 本轮验证

- 工程验证：`npm run check`、`npm run lint`、`npm test`、`npm run build` 通过。现有测试不能证明新页面的审美质量。
- 浏览器观察：三站分别检查桌面和 390px 手机布局，检查图片、主要锚点与内容入口；未观察到横向溢出。品牌站手机菜单选择后收起，场景问题可互斥展开。
- 交互实操：产品站可从目标推进到初稿和人的判断，确认与调整均有可见反馈；社区滑杆改变图形，SVG 下载和方法复制已实操。产品工作台为本地演示，没有真实 AI 执行。
- 发布与验收：仅本地预览，未提交、推送、打包或发布。用户尚未验收，视觉质感是否达到其预期仍为 `UNVERIFIED`。
