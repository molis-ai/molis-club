## 已定位对象：关于页的代码演示卡

路由：`/about#ab-trio-title`。区域：「三种媒介，同一个动作」中的「代码」卡；状态：「修改」。外层为网页纵向滚动，内层为 `.ab-panel-in` 的纵向滚动。它演示代码与文字的修改过程，不是滚动机制教学。

定位前 `about.css` 与 HEAD 无差异；现有 `content/site/about.ts` 的其他改动保留。本次修改 `app/(site)/about/about.css` 与 `app/(site)/about/trio.tsx`，未改演示文案、播放状态机、企业页、共享样式、首页或视频。

### 改前证据

```css
.ab-trio .m-window-frame {
  width: 100%;
  max-height: 44svh;
}
.ab-panel-in {
  position: absolute;
  inset: 0;
  display: flex;
  flex-direction: column;
  gap: 18px;
  padding: clamp(16px, 1.8vw, 26px);
  overflow: auto;
}
```

代码卡在「修改」态有 11 个块级代码行。每行 `13px × 1.85 = 24.05px`，不计任何折行，代码已需要 264.55px。再加标题、两段间距、末端效果链接与面板内边距，所需高度大于固定窗高：

| 视口       | 改前窗口最多高度 | 内容最低高度估算 | 结论                   |
| ---------- | ---------------: | ---------------: | ---------------------- |
| 1440 × 900 |            396px |       约 420.6px | 即使代码不折行也放不下 |
| 900 × 700  |            308px |       约 401.2px | 折行还会进一步增高     |
| 390 × 844  |       约 371.4px |       约 400.8px | 手机单列仍有内部滚动   |

以上为当前 CSS、文本行数和视口计算出的下界，不是浏览器测量值。原实现靠内部 `overflow:auto` 保留末端内容，因此没有把它称为“内容被删除”；问题是阅读代码与操作「效果」需要再进入一个滚动区。

### 本次修复

1. 移除三张窗口的 `44svh` 高度上限。绘画窗口保留原宽高比；代码与文字窗口设为 `aspect-ratio:auto`，由内容定高，桌面三列共用行高。
2. 代码与文字内容回到正常文档流，移除绝对定位与内部 `overflow:auto`。代码保留原有折行能力，不缩小字号、不截断代码。
   面板外框明确使用 `min-height: min-content`，避免共享的 `overflow:hidden` 比例盒把内容最小高度降为零。
3. 沿用企业页已有的 CSS `subgrid` 做法，让桌面三列共用「标签—画面—图注」三行。代码卡增高时，另外两张窗口一起对齐；手机仍按原断点单列排列。
4. 三个代码草稿、三个文字草稿分别共占同一个网格格子，按真实文本及折行预留最大高度。非当前稿 `visibility:hidden` 且 `aria-hidden`，其中没有可聚焦元素。标题和「效果」链接各保留一份，切换仍沿用原入场动画。
5. 手机文本卡保留原窗口尺度作为最小高度，完整内容可以继续撑高。外层 `.ex-screen` 原本只有最小高度，没有固定高度或纵向裁切，会随内容增长。无需监听滚轮、测量 DOM 或新增状态。

需要接受的排版变化：该段允许超过一屏高，通过页面滚动阅读完整内容。没有为了维持一屏而缩字或裁切；短草稿会保留为长草稿预留的留白，避免自动演示推移后续段落。最终切换稳定性仍需浏览器复验。

可用于浏览器只读诊断的片段：

```js
Array.from(document.querySelectorAll('.ab-trio .m-window-frame')).map(
  (frame) => {
    const panel = frame.querySelector('.ab-panel-in');
    const box = frame.getBoundingClientRect();
    return {
      top: box.top,
      bottom: box.bottom,
      height: box.height,
      panel: panel && {
        clientHeight: panel.clientHeight,

);
```

## 当前证据边界

主会话实测明确了两个根因：

- 只移除内部滚动仍会裁切，因为外层比例盒保持固定高度。900 × 700 下曾出现窗口 331px、内容 504px。必须同时解除文本框宽高比约束，并让内容决定行高。
- 解除比例后已实测三组视口、三个状态均无裁切、无内部滚动、桌面三列对齐；但 900 × 700 的三个状态高度为 331／521／473px，手机代码卡为 208／400／376px，自动演示会推移下方内容。因此最终版本用三个真实草稿共同占位稳定高度。

- 已完成：代码路径、内容行数、固定尺寸与父级约束检查；真实草稿占位修复；改前片段留档；局部 `oxlint`、格式检查与 `git diff --check`。
- 主会话已在独立 3001 本地预览核对最终三组视口 × 三个步骤：1440×900 的三张窗口均约 529px、整段 684px；900×700 的窗口均约 521px、整段 669px；390×844 的绘画／代码／文字窗口约 376／400／372px、整段 1555px。每个视口下三个步骤高度一致；两张文字面板均 `scrollHeight === clientHeight === parentHeight`，无横向溢出，桌面三窗口上下对齐。
- 隐藏草稿无可聚焦节点，当前仅两份草稿可见（代码与文字各一份），效果链接仅一份。该链接按 Enter 后到达 `#beliefs`。减少动态重载后为完成态、没有自动播放；禁用 JavaScript 重载后仍为完成态且文本完整，步骤控件隐藏。验证后恢复浏览器设置。
- 恢复正常窗口后，在代码卡内滚动：页面 `scrollY` 从约 1580.6 变为 1847.2，两张文字卡的 `scrollTop` 仍为 0；滚动由整页承接，没有困在卡片内。
- 工程：`npm run check`、`npm run lint`、29 项单元测试通过；独立快照 `npm run build` 通过。主会话没有重建或停止 3000 视频服务。
- 用户验收 `UNVERIFIED`：三种媒介一段的阅读节奏、窗口尺度与视觉一致性。
- 没有宣称会议中所有未指明的内层滚动均已定位，也没有改动仍有明确用途的滚动。
