# Molis AI：最初版 Edition C 的设计偏好与要求

整理日期：2026-10-08。

适用版本：最初版 Edition C（`/edition-c`），包括形成这一版时的探索与细节调整。

本文总结一骏在最初版 Edition C 设计阶段表达的偏好。出现多次调整的地方，以该阶段最后一次明确确认为准；区分当时的审美方向、具体页面要求，以及已经撤销的探索方案。文中的“当前”“最终”“最后确认”均指这一阶段，不代表后续版本或整个网站的永久要求。

这是一份阶段性设计意图记录，不代表一骏已验收所有实现，也不把本版的具体效果自动变成其他版本或产品的硬性规则。后续改版以新的明确要求为准。仓库视觉系统见 [DESIGN.md](../DESIGN.md)，C 版需求与历次验收原在 `specs/edition-c/spec.md`（2026-10-16 移出工作区，见 Git 历史）；这些文档可能继续演进，不作为最初版的固定快照。

## 核心方向

像一家有审美的设计师工作室：简约、宁静、有艺术感。靠排版、图像和细腻交互建立质感，而不是靠堆内容和装饰。

浓缩原则：让内容有主次，让画面有呼吸，让交互有反馈；少一点界面噪声，多一点工作室自己的气质。

## 1. 信息呈现：先分配注意力，再决定放什么

- 用户进入页面，应当很快理解“这是一个与 AI 一起创作的工作室”。
- 不喜欢文字过多、模块过多、多个重点同时争抢注意力。内容展示需要有意安排注意力，而不是把所有信息平铺出来。
- 首页不需要把所有栏目和能力逐一介绍完，更重视第一印象、氛围和清晰的入口。原有的下方模块可以删除或重组。
- 内容可以精简、合并、重写，功能与信息结构也可以酌情重做，不必迁就现有实现。
- 不在页面中出现“移动鼠标”“轻点空白处”等操作教学文案。交互应当自然被发现。
- 需要一定的 SEO、GEO。结合本次对简洁的要求，落实时应兼顾内容可发现性与前台阅读体验，不用堆砌文案制造信息负担。

## 2. 布局：有留白，但不是机械地空着

- 喜欢明确的主次、完整的大画面，以及紧凑、有组织的文字组合。
- 留白要服务构图，不能因为技术实现而出现突兀的空隙。例如，短单词不应继续占用最长单词的空间，导致词间距离过大。
- 首页底部保留 MolisAI 大字标，但全屏时不能过大、压过其他内容。最后一次调整要求是“稍微变小一点”，具体缩小比例是本轮实现选择，不是永久设计常量。
- 主文案相对克制，与底部字标形成尺度差异。
- 每个页面都要针对自己的内容设计，包括目录、详情、观点、百科和登录，不能只做好首页，也不能机械套用同一套模块。

## 3. 导航与内容归属：清楚、轻量、可直接找到

### 最后确认的导航方向

- 顶部文字目录字号缩小后直接铺开。
- 登录保留在右上角，登录页面本身也要有同等设计质感。
- 主要栏目为社区、百科、产品、解决方案、观点。
- “文章”改称“观点”。
- Artist Skill 属于百科，不作为独立一级栏目。

曾考虑用下拉菜单减少拥挤，但后来的明确选择是“小字号、直接展开”。不要把已经被替代的下拉方案当成当前硬性要求。

### 内容之间的关系

- 社区连接成员介绍、成员作品与作品体验入口，不只是展示成员名单。
- 百科承载工作室对外输出的知识与创作能力，包括前端网页词典、动效百科、配套 Prompt、艺术家 Skill 系列，以及其他辅助能力。
- 百科中的内容要能被带走使用，例如选择合适的动效与 Prompt，在用户本地使用。
- 产品、解决方案和观点拥有适合各自内容的页面表达。

## 4. 字体与排版：整体关系比某一款字体更重要

- 没有指定某一款字体作为硬性要求，更看重大小、位置、字距、重量和整体排布。
- 最后最明确偏好的是 [Everyday](https://everyday.io/)：不只是借鉴氛围，还希望深入参考顶部文字排列、字样式、首页布局和内页设计。
- 大字可以成为设计主体，但不能一味放大；导航与辅助信息应当轻巧。
- 循环英文标题保持一行，单词之间使用自然间距。
- 排版要稳定。结合已接受的实现方向，输入过程中保留当前词组的宽度，换词时再平滑调整，避免每出现一个字母就让整句话跳动。

## 5. 动效：有设计感，也保持宁静

### 希望具备的交互

- 背景对鼠标移动和操作产生反馈。
- 图片 Hover 时出现遮挡、幕面或类似的揭示效果。
- 菜单 Hover 时有视觉变化、渐变和细腻动效。
- 向下浏览页面时，有结合内容的动态变化。
- 在各处加入合适的交互，而不是为所有元素机械添加同一种动画。

动效的目的，是让网站拥有设计工作室的质感。它应当与内容和注意力分配相配合，不能用热闹替代设计，也不依赖解释性文案才能成立。

### 首页底部 MolisAI 字标

- 按字母顺序打字出现。
- 最后一个 I 出现后，再出现置底短横输入光标。
- 需要的是底部短横光标，不是常规竖线光标。
- 整行淡入、流水式或瀑布式出现是之前探索过的方案，最终选择是打字机。

### 首页上方的 AI 词组

- 使用约八组以 A、I 开头的词组循环播放，保持一行。
- A、I 始终保留，其余字母出现与切换。
- 按整句话的阅读顺序逐字输入：先打完第一个词，再接着打第二个词，不是两个单词同时打字。
- 短词不能留下突兀的大空隙。
- 后续已接受 A、I 在换词时平滑移动，让整组按当前词长自然居中。因此，“固定 A、I”在最终方案中指始终可见，不再要求始终保持同一个横坐标。
- 本轮采用“输入 → 停留阅读 → 退格 → 下一组”的节奏。具体速度与停留时长属于实现参数，可根据实际体验继续调整。

## 6. 视觉风格与图像：克制的艺术感

- 核心关键词：高级设计师工作室、简约、宁静、艺术感、细腻。
- 不喜欢过多线条、箭头、按钮和零碎装饰造成的视觉噪声。
- 图像承担较大的氛围表达作用，文字和界面退到合适的位置。
- 喜欢安静的创作场景、自然光和有艺术感的画面，也曾探索插画、波纹流动视频或动态背景。
- 参考方向先后包括 [Nick Clement](https://nickclement.com/?ref=siteinspire)、[Monolog](https://bymonolog.com/) 和 [Everyday](https://everyday.io/)。最后最明确的整体风格偏好是 Everyday；Monolog 的菜单 Hover 和流动背景仍体现了对交互品质的期待。
- 参考网站提供表达方式，内容与品牌使用我们自己的。

### 已撤销的图片约束

曾提出恢复旧插画、用新风格重画旧内容、使用窗边阅读照片、围桌交流人物，以及让文字落在图片中间偏左的墙面区域等探索。

后来明确要求“忽略我对图的要求”，按 Everyday 的整体方向重新设计。因此：

- 不把某张旧图、某种旧画风、窗边阅读或围桌人物当成当前硬性要求。
- 中间偏左的文字位置是针对当时图片构图的建议，不是所有页面都应套用的永久布局规则。
- 没有视频时可以用合适的静态图像承载宁静氛围，不必为了形式而强行使用视频。

## 7. 设计协作与迭代方式

- 喜欢看到可操作、可发布的真实页面，再根据实际体验调整。
- 探索新方案时保留现有版本供比较。会话中先要求完成 A，再完成 B，后来又探索 C。
- 保留版本用于比较，不等于在代码中复制归档；历史实现的保存方式遵循仓库约定。
- 一套设计要覆盖全站，每个页面适配对应内容，不能只交付漂亮的首页。
- 允许推翻不合适的功能与信息结构，不要求设计迁就历史实现。
- 反复调整时，保留已确认的方向，及时替换已经被用户纠正的要求，不让过时约束继续影响新方案。

## 延续最初版 Edition C 方向时的快速核对

1. 第一眼是否清楚表达工作室身份，并有明确的视觉重点？
2. 文字、模块、线条、按钮和箭头是否真的有必要？
3. 留白是否来自构图判断，而不是机械预留空间？
4. 大字、主文案、导航与辅助信息是否各有合适的分量？
5. 动效是否与内容有关，能够自然发现，并保持安静的整体气质？
6. 每个页面是否根据自己的内容组织，而不是只换标题和图片？
7. 是否误把已经撤销的图片、菜单或动画方案当成当前要求？
